    Floating-point representation

    A computer stores a real number the way scientific notation does: a sign, a few significant digits (the mantissa), and an exponent that slides the decimal point. The catch: only finitely many digits fit, so the representable numbers are a finite set of ticks on the real line — dense near zero, sparse far away. Everything in numerical computing follows from that picture.

    Definition An IEEE-754 binary floating-point number is $x = (-1)^s \cdot (1.m_1m_2\dots m_p)_2 \cdot 2^{e}$ with sign bit $s$, $p$ mantissa bits, and exponent $e$ in a fixed range. float64: $p=52$, $e \in [-1022, 1023]$; float32: $p=23$, $e\in[-126,127]$; float16: $p=10$, $e\in[-14,15]$; bfloat16: $p=7$, $e\in[-126,127]$. Special values: $\pm 0$, $\pm\infty$, NaN, and subnormals (leading 0 instead of 1) filling the gap near zero. Machine epsilon $\varepsilon = 2^{-p}$ is half the gap between 1 and the next float ($2^{-52}\approx 2.2\times10^{-16}$ for float64).
    Worked example Represent $0.1$ in binary: $0.1 = (0.0001100110011\overline{0011})_2$ — infinitely repeating, so no binary float stores it exactly. float64 rounds it to $0.1000000000000000055511151231257827\ldots$, which is why 0.1 + 0.2 == 0.3 is false: the stored $0.1+0.2$ rounds to $0.30000000000000004$, but the stored $0.3$ rounds to $0.29999999999999998\ldots$ — different floats.
    Explore

    Slide the mantissa bits and watch the representable numbers tick along the number line: gaps double at every power of 2.

    Pitfall Never compare floats with ==; use a tolerance mixing absolute and relative parts: abs(a-b) <= atol + rtol*abs(b). Purely relative tolerance fails near zero; purely absolute fails for large magnitudes.
    Where this goes bfloat16's wide exponent / short mantissa trade-off is exactly why it is the default for training LLMs — see mixed precision below and Ch 23.
    Drill
    1. EASY What is the gap between consecutive float64 numbers just above 1? Just above $2^{20}$?
      Solution
      Above 1: $2^{-52}\approx 2.22\times10^{-16}$. Above $2^{20}$: $2^{20-52} = 2^{-32}\approx 2.33\times10^{-10}$ — the gap scales with magnitude.
    2. MED What is the largest integer $n$ such that all integers $0..n$ are exactly representable in float32? In float64?
      Solution
      Integers are exact until the gap exceeds 1, i.e. up to $2^{p+1}$: float32: $2^{24} = 16{,}777{,}216$; float64: $2^{53} \approx 9.0\times10^{15}$. Above that, adding 1 can be a no-op: in float32, $2^{24} + 1$ rounds back to $2^{24}$.
    3. HARD bfloat16 and float16 both use 16 bits. Compute each format's machine epsilon and largest finite value, and say which failure mode each risks in deep learning.
      Solution
      float16: $\varepsilon = 2^{-10} \approx 9.8\times10^{-4}$; max $= (2-2^{-10})\cdot 2^{15} = 65504$. bfloat16: $\varepsilon = 2^{-7} \approx 7.8\times10^{-3}$; max $\approx 3.4\times10^{38}$ (same exponent range as float32). float16 risks overflow/underflow (loss scaling needed: gradients above 65504 become inf); bfloat16 risks precision loss (only ~2-3 decimal digits) but almost never overflows — the trade Google made for TPUs.

    Floating-point error

    Every arithmetic operation on floats rounds its true result to the nearest representable number. One rounding is tiny — a relative error of at most $\varepsilon$ — but errors accumulate, cancel catastrophically, or get amplified by later steps. The discipline is to track relative error through a computation.

    Definition The standard model of floating-point arithmetic: for each basic operation $\circ \in \{+,-,\times,\div\}$, the computed result satisfies $\mathrm{fl}(x\circ y) = (x\circ y)(1+\delta)$ with $|\delta| \le \varepsilon$ (unit roundoff, $2^{-53}$ for float64 round-to-nearest). The relative error of $\hat x$ approximating $x\ne0$ is $|\hat x - x|/|x|$.
    Worked example Catastrophic cancellation: compute $f(x) = \sqrt{x+1}-\sqrt{x}$ at $x = 10^{12}$ in float64. $\sqrt{10^{12}+1} \approx 10^6 + 5\times10^{-7}$; both square roots are $\approx 10^6$ and agree to 12 digits, so their difference keeps only ~4 significant digits. The rewrite $f(x) = \frac{1}{\sqrt{x+1}+\sqrt{x}}$ computes the same value with full precision: $\approx 5.0\times10^{-7}$ with ~16 good digits. Same math, wildly different arithmetic.
    Pitfall Subtracting nearly equal numbers does not create error — it exposes error already present in the operands by stripping away the agreeing leading digits. The subtraction itself is exact (Sterbenz: if $y/2 \le x \le 2y$, $x - y$ is exactly representable). Blame the upstream roundings.
    Drill
    1. EASY In float arithmetic with $\varepsilon = 10^{-16}$, roughly what relative error can $\mathrm{fl}(a+b)$ have? What absolute error if $a+b \approx 10^8$?
      Solution
      Relative: up to $\sim 10^{-16}$. Absolute: $10^8 \times 10^{-16} = 10^{-8}$.
    2. MED The quadratic formula root $x = \frac{-b + \sqrt{b^2-4ac}}{2a}$ loses precision when $b > 0$ and $|4ac| \ll b^2$. Why, and what is the fix?
      Solution
      $\sqrt{b^2-4ac}\approx |b|$, so the numerator subtracts nearly equal quantities. Fix: compute the well-conditioned root first, $x_1 = \frac{-b-\mathrm{sign}(b)\sqrt{b^2-4ac}}{2a}$ (an addition of like signs), then get the other from Vieta: $x_2 = \frac{c}{a x_1}$.
    3. HARD Summing $n$ floats left-to-right gives worst-case relative error $\approx n\varepsilon$ (times a condition factor). Kahan compensated summation gets $O(\varepsilon)$ independent of $n$. Explain its trick: y = x - c; t = s + y; c = (t - s) - y; s = t.
      Solution
      After $t = s + y$, the quantity $(t - s)$ recovers the part of $y$ that actually made it into the sum (exactly, by Sterbenz-type arguments when magnitudes are comparable); subtracting $y$ yields the negative of the lost low-order bits. Storing that in $c$ and subtracting it from the next addend re-injects the lost tail each step. Errors no longer accumulate linearly; the computed sum is accurate to $O(\varepsilon)$ plus a tiny $O(n\varepsilon^2)$ term.

    Rounding error

    Rounding error is the error from squeezing a true value onto the float grid. IEEE default is round-to-nearest-even: pick the closest float, and on an exact tie pick the one with even last bit (so ties don't drift upward). Each rounding is bounded and unbiased-ish; the game is how roundings compound.

    Definition Round-to-nearest gives $|\mathrm{fl}(x) - x| \le \tfrac12 \mathrm{ulp}(x)$, i.e. relative error $\le u = \tfrac12 \cdot 2^{-p} = \varepsilon/2$ where ulp is the "unit in the last place" (the local grid spacing). Accumulation: computing $\prod_{i=1}^n x_i$ by repeated multiplication yields $\hat P = P\prod (1+\delta_i)$, so relative error $\lesssim n u$ for $nu \ll 1$.
    Worked example With a 3-decimal-digit toy format, round $2.3456$: nearest is $2.35$ (error $0.0044$, relative $\approx 0.19\%$, within half of the last-digit unit $0.005/2.35$). Now compute $(2.35)^2 = 5.5225 \to 5.52$: two roundings so far. True $(2.3456)^2 = 5.5018\ldots$ — the computed $5.52$ carries both the input rounding (amplified by squaring: doubles the relative error) and the output rounding.
    Think first You add $10^7$ copies of $0.1$ in float32 ($u \approx 6\times10^{-8}$). Roughly how far from $10^6$ can the naive left-to-right sum be?
    Reveal
    Relative error can reach $\sim n u \approx 10^7 \times 6\times10^{-8} = 0.6$, i.e. tens of percent — and in practice the sum stalls: once the running total is large, each new $0.1$ is below half an ulp and rounds to nothing. Actual experiment: the float32 sum plateaus near $1.09\times10^6$'s wrong-neighborhood (classic result $\approx 1{,}087{,}937$ in some orders) — pairwise or Kahan summation fixes it.
    Drill
    1. EASY Round to 4 significant digits with round-to-nearest-even: $3.14159$, $2.71828$, $1.0005$ (tie).
      Solution
      $3.142$; $2.718$; the tie $1.0005$ goes to the even last digit: $1.000$ (not $1.001$).
    2. MED Why round-to-nearest-even rather than round-half-up?
      Solution
      Half-up rounds every tie in the same direction, injecting a systematic upward bias that accumulates over many operations (e.g. financial totals, long simulations). Ties-to-even alternates direction statistically, canceling the bias to first order.
    3. HARD Show that for $nu < 0.1$, $\prod_{i=1}^n (1+\delta_i)$ with $|\delta_i|\le u$ satisfies $|\prod(1+\delta_i) - 1| \le 1.06\, nu$ (the "$\gamma_n$" bound).
      Solution
      $\left|\prod(1+\delta_i)-1\right| \le (1+u)^n - 1 = e^{n\ln(1+u)}-1 \le e^{nu}-1$. For $x = nu \le 0.1$: $e^x - 1 \le x\frac{e^{0.1}-1}{0.1} \approx 1.0517x \le 1.06\,nu$ (using convexity of $e^x-1$: the chord from 0 to 0.1 lies above). Hence relative error grows at most (essentially) linearly in the number of roundings.

    Truncation error

    Truncation (discretization) error comes from the algorithm, not the arithmetic: you replaced an infinite process — a limit, a series, an integral — by a finite one. A finite difference instead of a derivative, a Riemann sum instead of an integral, ten Taylor terms instead of all of them. It exists even with exact real arithmetic.

    Definition If a method with step $h$ produces $A(h)$ approximating the true $A$, the truncation error is $A(h) - A$; the method has order $p$ if $A(h) - A = O(h^p)$ as $h\to0$. Taylor's theorem is the universal source: $f(x+h) = f(x) + hf'(x) + \tfrac{h^2}{2}f''(x) + \dots + \tfrac{h^k}{k!}f^{(k)}(\xi)$.
    Worked example Forward difference $D_h = \frac{f(x+h)-f(x)}{h}$. Taylor: $f(x+h) = f(x) + hf'(x) + \frac{h^2}{2}f''(\xi)$, so $D_h = f'(x) + \frac h2 f''(\xi)$: truncation error $\approx \frac h2 f''(x)$, order 1. For $f = e^x$ at $x=0$, $h = 0.1$: $D_h = \frac{e^{0.1}-1}{0.1} = 1.05171$, error $0.0517 \approx \frac{0.1}{2}\cdot 1$. ✓ Halving $h$ halves the error.
    Where this goes Truncation vs rounding is THE trade-off of numerical differentiation (below): shrinking $h$ kills truncation error but feeds cancellation. Euler vs Runge-Kutta in Ch 10 is order-1 vs order-4 truncation.
    Drill
    1. EASY Approximating $e = \sum_{k\ge0} 1/k!$ by the first 5 terms (through $1/4!$): compute the truncation error.
      Solution
      $S_5 = 1+1+\tfrac12+\tfrac16+\tfrac1{24} = 2.708\overline{3}$; $e = 2.718281\ldots$; error $\approx 0.00995$ — about the next term $1/5! = 0.008\overline{3}$ (plus tail).
    2. MED Show the central difference $\frac{f(x+h)-f(x-h)}{2h}$ has truncation error $\frac{h^2}{6}f'''(x) + O(h^4)$ — order 2.
      Solution
      Taylor both ways: $f(x\pm h) = f \pm hf' + \frac{h^2}2 f'' \pm \frac{h^3}6 f''' + O(h^4)$. Subtracting kills the even terms: $f(x+h)-f(x-h) = 2hf' + \frac{h^3}{3}f''' + O(h^5)$. Divide by $2h$: $f' + \frac{h^2}{6}f''' + O(h^4)$. ∎
    3. HARD A method has error $E(h) = c h^p$ with unknown $c, p$. You measure $E(0.1) = 4\times10^{-3}$ and $E(0.05) = 1\times10^{-3}$. Estimate $p$, and the $h$ needed for $E = 10^{-6}$.
      Solution
      $E(h)/E(h/2) = 2^p = 4 \Rightarrow p = 2$. Then $c = E(0.1)/0.01 = 0.4$. Need $0.4 h^2 = 10^{-6} \Rightarrow h = \sqrt{2.5\times10^{-6}} \approx 1.58\times10^{-3}$. (This halving-comparison is Richardson's technique for estimating order empirically.)

    Error propagation

    Errors flow through functions like signals through amplifiers: a function with a big derivative amplifies input error, one with a small derivative damps it. First-order error propagation is nothing but the linearization of Ch 9 applied to uncertainty.

    Definition If $\hat x = x + \Delta x$ and $y = f(x)$, then to first order $\Delta y \approx f'(x)\,\Delta x$; the relative errors relate by $\frac{\Delta y}{y} \approx \underbrace{\frac{x f'(x)}{f(x)}}_{\text{condition number } \kappa_f(x)} \cdot \frac{\Delta x}{x}$. For several inputs, $\Delta y \approx \sum_i \frac{\partial f}{\partial x_i}\Delta x_i$; for independent random errors, variances add: $\sigma_y^2 \approx \sum_i \left(\frac{\partial f}{\partial x_i}\right)^2 \sigma_{x_i}^2$.
    Worked example $y = x_1 x_2$ with 1% relative error in each input. $\frac{\Delta y}{y} = \frac{\Delta x_1}{x_1} + \frac{\Delta x_2}{x_2}$ (to first order): worst case 2%. But $y = x_1 - x_2$ with $x_1 = 1.00$, $x_2 = 0.99$, each known to $\pm 0.01$ (1%): $\Delta y = \pm0.02$ on $y = 0.01$ — a 200% relative error. Subtraction of close values is an error amplifier with gain $\frac{|x_1|+|x_2|}{|x_1-x_2|}$.
    Pitfall Adding relative errors is for products/quotients; adding absolute errors is for sums/differences. Mixing them up is the standard lab-course blunder. And first-order propagation lies when $f$ is strongly curved over the error interval — check $|f''|\Delta x^2$ against $|f'|\Delta x$.
    Drill
    1. EASY $y = x^3$, with $x$ known to 2% relative error. Relative error in $y$?
      Solution
      $\kappa = \frac{x\cdot 3x^2}{x^3} = 3$: about 6%.
    2. MED $z = \frac{a b^2}{\sqrt c}$ with independent relative standard errors 1%, 2%, 4%. Find the relative standard error of $z$ (variance rule).
      Solution
      Powers scale relative errors: contributions $1\%, 2\times2\% = 4\%, \tfrac12\times4\% = 2\%$. Independent ⟹ add in quadrature: $\sqrt{1 + 16 + 4}\% = \sqrt{21}\% \approx 4.6\%$.
    3. HARD $f(x) = \ln x$ near $x = 1$: compute $\kappa_f(x)$ and explain the blow-up. Then explain why the function log1p(t) $= \ln(1+t)$ exists in every numerical library.
      Solution
      $\kappa = \frac{x \cdot (1/x)}{\ln x} = \frac{1}{\ln x} \to \infty$ as $x\to1$: near 1, tiny relative input error swamps the tiny output $\ln x$. If you compute $\ln(1+t)$ for small $t$ by first forming $1+t$ (which rounds away digits of $t$: for $t=10^{-12}$, $1+t$ keeps only 4 digits of $t$ in float64) and then taking log, you inherit that damage. log1p takes $t$ directly and evaluates a series/rational approximation in $t$, giving full relative accuracy. Same story for expm1.

    Conditioning

    Conditioning is a property of the problem: how much does the exact answer move when the input wiggles? An ill-conditioned problem amplifies input uncertainty no matter how the answer is computed. Distinguish this fiercely from stability, which is a property of the algorithm.

    Definition The (relative) condition number of problem $x \mapsto f(x)$ is $\kappa = \lim_{\delta\to0}\sup_{\|\Delta x\|\le\delta\|x\|} \frac{\|f(x+\Delta x)-f(x)\|/\|f(x)\|}{\|\Delta x\|/\|x\|}$. For solving $Ax = b$: $\kappa(A) = \|A\|\,\|A^{-1}\|$; in the 2-norm, $\kappa_2(A) = \sigma_{\max}/\sigma_{\min}$ (ratio of singular values, Ch 8). Rule of thumb: with data accurate to $10^{-16}$ and $\kappa = 10^k$, expect no more than $\sim16-k$ correct digits in the answer.
    Worked example $A = \begin{pmatrix}1 & 1\\ 1 & 1.0001\end{pmatrix}$, $b = (2,\ 2.0001)^\top$: solution $x = (1,1)^\top$. Perturb $b$ to $(2,\ 2.0002)^\top$ — a relative change of $\sim 3.5\times10^{-5}$: new solution $x = (0, 2)^\top$, a relative change of order 1. Amplification $\sim 3\times10^4 \approx \kappa_2(A) \approx 4\times10^4$. The rows are nearly parallel lines; their intersection slides wildly.
    Explore

    Drag the condition number: watch the unit circle map to an ellipse under $A$, and two near-parallel constraint lines whose intersection (the solution) becomes hypersensitive.

    Where this goes $\kappa$ of the Hessian controls gradient descent's speed (Ch 15's conditioning topic); preconditioning and normalization layers (Ch 21) exist to shrink effective condition numbers.
    Drill
    1. EASY $A = \mathrm{diag}(100, 1)$. Compute $\kappa_2(A)$.
      Solution
      $\sigma_{\max}=100$, $\sigma_{\min}=1$: $\kappa_2 = 100$.
    2. MED Why is $\kappa(A) \ge 1$ always, and what does $\kappa = 1$ mean geometrically? Which matrices achieve it?
      Solution
      $1 = \|I\| = \|AA^{-1}\| \le \|A\|\|A^{-1}\| = \kappa$. $\kappa_2 = 1$ means the map stretches all directions equally — spheres to spheres: exactly the (nonzero) scalar multiples of orthogonal matrices. This is why orthogonal transforms (QR, rotations) are numerically beloved: they amplify nothing.
    3. HARD The Hilbert matrix $H_{ij} = 1/(i+j-1)$ has $\kappa_2(H_5) \approx 4.8\times10^5$. Solving $H_5 x = b$ in float64, how many digits of $x$ can you trust? Would computing in float32 and a "better algorithm" help?
      Solution
      $16 - \log_{10}(4.8\times10^5) \approx 16 - 5.7 \approx 10$ digits at best. float32 (7 digits) leaves $\sim1$ digit. No algorithm helps: conditioning bounds what ANY algorithm can do given rounded inputs — the problem itself is the amplifier. The only fixes change the problem: more input precision, or reformulation (e.g. use an orthogonal polynomial basis instead of the monomials that generate Hilbert matrices in least squares).
    A problem has κ = 10⁸. You solve it with a perfectly stable algorithm in float64 (u ≈ 10⁻¹⁶). What accuracy should you expect?
    A stable algorithm returns the exact answer to a nearby problem (backward error ~u); the condition number then amplifies that ~10⁻¹⁶ input-level error by 10⁸, leaving ~10⁻⁸ relative error: about 8 digits. Stability delivers everything conditioning permits — no more.

    Numerical stability

    Stability is the algorithm's side of the bargain: a stable algorithm does not add drama of its own. The gold standard is backward stability — the computed answer is the exact answer to a slightly perturbed question. Then the total error is neatly split: error ≈ (condition number of problem) × (backward error of algorithm).

    Definition An algorithm for $f$ is backward stable if for every input $x$ it returns $\hat y = f(\tilde x)$ for some $\tilde x$ with $\frac{\|\tilde x - x\|}{\|x\|} = O(u)$. Consequence (forward error bound): $\frac{\|\hat y - f(x)\|}{\|f(x)\|} \lesssim \kappa_f(x)\cdot O(u)$. Weaker notions: forward stable (error comparable to what a backward stable method would make), mixed stability.
    Worked example Two ways to compute the variance of $x = (10^8+1,\ 10^8+2,\ 10^8+3)$ (true variance 1, mean $10^8+2$). Textbook one-pass formula $\frac1n\sum x_i^2 - \bar x^2$: both terms $\approx 10^{16}$, agreeing in their first ~16 digits — float64 cancellation leaves garbage (often 0.0 or negative!). Two-pass formula $\frac1n\sum(x_i-\bar x)^2$: subtract first ($-1, 0, 1$ exactly, by Sterbenz), then square: exactly $2/3\cdot\ldots$ — precisely $\frac{1+0+1}{3}$ if using population variance $\frac1n$, $=0.666\ldots$, or 1 with the $\frac1{n-1}$ convention. Identical math; only one is stable.
    Pitfall "Unstable" does not mean "always wrong": the one-pass variance formula is fine when $\bar x$ is small relative to the spread. Instability means there EXIST reasonable inputs where the algorithm needlessly destroys accuracy. Test numerics at the edges, not the center.
    Where this goes Softmax and log-sum-exp (next) are the deep-learning face of stability; attention implementations (Ch 21/23) are one long exercise in keeping exponentials tame.
    Drill
    1. EASY Which is stable for computing $e^{-x}$ at large $x$: (a) $1/e^x$, (b) the alternating series $\sum (-x)^k/k!$?
      Solution
      (a). The series alternates with huge terms (for $x=20$, terms reach $\sim 4\times10^7$ while the answer is $2\times10^{-9}$): cancellation annihilates all correct digits. $1/e^x$ involves no cancellation (until $e^x$ overflows; then compute in log space).
    2. MED Solving $Ax=b$ by explicitly forming $A^{-1}$ then $x = A^{-1}b$ is discouraged versus LU-based solve. Give two reasons.
      Solution
      (1) Cost: inversion is $\sim 2n^3$ flops vs $\sim \frac23 n^3$ for LU solve — 3× more. (2) Stability/accuracy: LU with partial pivoting is backward stable in practice for the solve; forming $A^{-1}$ compounds rounding across $n$ solves and the product $A^{-1}b$ loses the residual-smallness guarantee. (Also inverses of sparse matrices are dense.)
    3. HARD Gaussian elimination WITHOUT pivoting on $A = \begin{pmatrix} 10^{-20} & 1\\ 1 & 1\end{pmatrix}$, $b = (1, 2)^\top$, in float64: trace what happens and compare with partial pivoting.
      Solution
      Multiplier $m = 1/10^{-20} = 10^{20}$. Row 2 becomes $(0,\ 1 - 10^{20})$; in float64, $1 - 10^{20}$ rounds to $-10^{20}$; RHS: $2 - 10^{20} \to -10^{20}$. Back-substitute: $x_2 = 1$; then $10^{-20}x_1 + 1 = 1 \Rightarrow x_1 = 0$. True solution $\approx (1, 1)$: $x_1$ is 100% wrong. With partial pivoting (swap rows): multiplier $10^{-20}$, no blow-up: $x \approx (1,1)$ to full precision. Tiny pivots manufacture huge multipliers that swamp the data — pivoting is a stability device, not a formality.

    Log-sum-exp trick

    Probabilities multiply into underflow ($10^{-5000}$ is a perfectly ordinary likelihood) and exponentials overflow at a mere $x \approx 709$ in float64. The cure: live in log space, and whenever you must sum probabilities, use log-sum-exp with the max factored out. It is the single most-used stability trick in machine learning.

    Definition $\mathrm{LSE}(x_1..x_n) = \log\sum_i e^{x_i}$. Stable evaluation: with $M = \max_i x_i$, $$\mathrm{LSE}(x) = M + \log\sum_i e^{x_i - M}.$$ Every exponent $x_i - M \le 0$: no overflow, and at least one term is $e^0 = 1$: the log's argument lies in $[1, n]$ — perfectly conditioned. Softmax follows: $\mathrm{softmax}(x)_i = e^{x_i - \mathrm{LSE}(x)} = \frac{e^{x_i - M}}{\sum_j e^{x_j - M}}$.
    Worked example Logits $x = (1000, 1001, 1002)$. Naive: $e^{1000}$ overflows to inf; softmax = inf/inf = NaN. Stable: $M = 1002$, shifted $(-2,-1,0)$, exponentials $(0.1353, 0.3679, 1)$, sum $= 1.5032$, $\log = 0.4076$; $\mathrm{LSE} = 1002.4076$. Softmax $= (0.0900, 0.2447, 0.6652)$ — the same answer $(e^{-2},e^{-1},1)/1.5032$ that logits $(0,1,2)$ give: softmax is shift-invariant, and the trick just exploits that.
    Think first Cross-entropy loss needs $\log(\mathrm{softmax}(x)_y)$. Why is computing softmax first and then taking log a bad idea, and what is the right formula?
    Reveal
    For a badly-losing class, softmax$_y$ underflows to exactly 0 (e.g. $e^{-800}$), then $\log 0 = -\infty$ and the gradient NaNs. Fuse them: $\log\mathrm{softmax}(x)_y = x_y - \mathrm{LSE}(x)$, computed with the stable LSE — always finite. This is why frameworks ship log_softmax and cross_entropy-from-logits and warn against feeding probabilities.
    Drill
    1. EASY Compute $\mathrm{LSE}(-1200, -1201)$ stably.
      Solution
      $M = -1200$: $-1200 + \log(1 + e^{-1}) = -1200 + \log(1.3679) = -1200 + 0.3133 = -1199.6867$. Naive evaluation: both $e^{-1200}$ underflow to 0, $\log 0 = -\infty$: wrong.
    2. MED An HMM's likelihood is a product of 10,000 per-step probabilities averaging 0.1. Show why you must work in log space, and give the log-likelihood.
      Solution
      Product $\approx 10^{-10000}$, far below float64's smallest subnormal ($\approx 5\times10^{-324}$): underflows to 0 within ~320 factors. Log space: $\sum \log p_t \approx 10^4\ln 0.1 \approx -23{,}026$ — a perfectly comfortable float.
    3. HARD Prove the bounds $M \le \mathrm{LSE}(x) \le M + \log n$ and $\mathrm{LSE}(x) \ge \frac{1}{n}\sum_i x_i$… prove the first pair, and show LSE is a smooth approximation to max with error $\to 0$ as logits spread.
      Solution
      Lower: $\sum e^{x_i} \ge e^M$, so LSE $\ge M$. Upper: $\sum e^{x_i} \le n e^M$, so LSE $\le M + \log n$. Thus $|\mathrm{LSE}(x) - \max_i x_i| \le \log n$ always; when the max leads the runner-up by gap $g$, $\mathrm{LSE} = M + \log(1 + \sum_{i\ne\arg\max} e^{x_i - M}) \le M + \log(1 + (n{-}1)e^{-g}) \to M$. LSE (scaled: $\tau\,\mathrm{LSE}(x/\tau)$) is the softmax temperature story of Ch 23.

    Mixed precision

    Modern accelerators do half-precision matrix multiplies several times faster than float32, at half the memory. Mixed-precision training spends the cheap format where errors wash out (the giant matmuls) and keeps the expensive format where errors accumulate (accumulations, weight updates, normalizations). Getting this split right is a pure numerical-analysis exercise, done at datacenter scale.

    Definition A standard mixed-precision recipe: store activations/weights for compute in fp16/bf16; accumulate matmul partial sums in fp32 (tensor cores do this natively); keep a master copy of weights in fp32 for the optimizer update; compute reductions (norms, softmax sums, losses) in fp32. With fp16 (narrow exponent), add loss scaling: multiply the loss by $s$ (e.g. $2^{14}$) so gradients shift up into representable range, then divide by $s$ before the update; skip steps whose gradients contain inf/NaN and lower $s$ ("dynamic loss scaling").
    Worked example Why the fp32 master weights: a weight $w = 1.0$ receives update $\eta g = 10^{-4}$ each step… wait, in bf16 the gap at 1.0 is $2^{-7}\cdot\ldots$ precisely $2^{-7} \approx 0.0078$: adding $10^{-4}$ rounds to no change — the weight never moves, learning silently stops. In fp32 the gap at 1.0 is $\approx 1.2\times10^{-7}$, so $10^{-4}$ registers fine. Update in fp32, then round the result to bf16 for the next forward pass.
    Pitfall bf16 and fp16 fail differently: fp16 overflows (max 65504 — attention logits and gradient spikes exceed it), bf16 loses precision (3 decimal digits — long sums drift). Variance-type statistics in normalization layers are the classic place half precision quietly corrupts training.

    Numerical differentiation

    Approximate a derivative by a difference quotient and you face a beautiful tug-of-war: truncation error shrinks with $h$, but cancellation error grows as $1/h$ — the two curves cross at an optimal $h$, and pushing beyond it makes things worse. This U-shaped error curve is the signature plot of numerical analysis.

    Definition Forward difference: $\frac{f(x+h)-f(x)}{h} = f'(x) + O(h)$. Central: $\frac{f(x+h)-f(x-h)}{2h} = f'(x) + O(h^2)$. With rounding error $\sim u|f(x)|$ in each evaluation, total error for central differences $\approx \frac{h^2}{6}|f'''| + \frac{u|f|}{h}$, minimized at $h^* \sim (3u|f|/|f'''|)^{1/3} \sim u^{1/3}$ — about $6\times10^{-6}$ in float64 — giving error $\sim u^{2/3} \approx 10^{-11}$, never full precision. (Forward: $h^*\sim u^{1/2}\approx10^{-8}$, error $\sim u^{1/2}\approx10^{-8}$.)
    Worked example $f(x) = e^x$ at $x = 0$ (true $f' = 1$), central differences in float64: $h = 10^{-1}$: error $\approx 1.7\times10^{-3}$; $h = 10^{-5}$: error $\approx 10^{-11}$ (near optimum); $h = 10^{-13}$: $e^{\pm h}$ agree to 13 digits, difference has ~3 good digits: error $\approx 10^{-4}$. Smaller $h$ made it 10 million times worse.

    Numerical integration

    To integrate numerically, sample the function and weight the samples. The classical ladder — midpoint, trapezoid, Simpson — comes from integrating interpolating polynomials of rising degree; Gaussian quadrature chooses even the sample points optimally; and in high dimensions all of it collapses and Monte Carlo takes over.

    Definition On $[a,b]$ split into $n$ panels of width $h = (b-a)/n$: Trapezoid $T_n = h\left(\frac{f_0}2 + f_1 + \dots + f_{n-1} + \frac{f_n}2\right)$, error $-\frac{(b-a)h^2}{12}f''(\xi) = O(h^2)$. Simpson (even $n$): $S_n = \frac h3(f_0 + 4f_1 + 2f_2 + 4f_3 + \dots + f_n)$, error $O(h^4)$, exact on cubics. Gauss–Legendre with $n$ nodes: exact on polynomials of degree $2n-1$. Monte Carlo: $\frac{b-a}{N}\sum f(X_i)$, $X_i$ uniform: error $O(N^{-1/2})$ in any dimension.
    Worked example $\int_0^1 e^x dx = e - 1 = 1.718282$. Trapezoid, $n=2$ ($h=\tfrac12$): $\tfrac12(\tfrac{1}{2} + e^{0.5} + \tfrac{e}{2}) = \tfrac12(0.5 + 1.648721 + 1.359141) = 1.753931$; error $+0.03565$. Simpson, $n=2$: $\frac{1/2}{3}(1 + 4e^{0.5} + e) = \frac16(1 + 6.594885 + 2.718282) = 1.718861$; error $+0.00058$ — 60× better from the same three samples.
    Pitfall High-order rules assume smoothness: on a kinked integrand like $\int_0^1 |x - \tfrac13| dx$, Simpson degrades to $O(h^2)$-ish unless you split the interval at the kink. And the curse of dimensionality: a product grid with $m$ points per axis costs $m^d$ evaluations — in $d = 100$, hopeless; Monte Carlo's $N^{-1/2}$ doesn't care about $d$, which is why Ch 13's estimators run the show in ML.

    Root finding

    Root finding — solve $f(x) = 0$ — is the primitive that optimization, equilibrium computation, and implicit equations all reduce to. The methods form a speed/safety spectrum: bisection (slow, bulletproof), fixed-point iteration (simple, conditional), Newton (blazing, temperamental), with hybrids like Brent's method taking the best of each.

    Definition A root (zero) of $f$ is $x^*$ with $f(x^*) = 0$; it is simple if $f'(x^*) \ne 0$. Convergence of an iteration $x_{k+1} = \Phi(x_k)$ with errors $e_k = |x_k - x^*|$: linear if $e_{k+1} \le \rho e_k$ ($\rho<1$), quadratic if $e_{k+1} \le C e_k^2$ (digits double), order $q$ if $e_{k+1}\le Ce_k^q$.
    Worked example $f(x) = x^2 - 2$ (root $\sqrt2 \approx 1.41421356$). Compare from the bracket $[1,2]$ / start 1.5: bisection gains 1 bit per step, needs ~50 steps for float64 accuracy; Newton (next sections show the mechanics) reaches full precision in 4 steps. But on $f(x) = \mathrm{sign}(x)\sqrt{|x|}$, Newton oscillates forever while bisection strolls to the root. Speed and robustness are different axes; production solvers (Brent) bracket with bisection and pounce with fast steps when safe.
    Where this goes Optimization is root finding on the gradient: Ch 15's Newton method solves $\nabla f = 0$. Implicit layers and deep-equilibrium models solve root problems inside networks.

(Simple roots: $|x-x^*| \approx \epsilon/|f'|$, full precision.) Multiplicity also degrades Newton from quadratic to linear (rate $\frac{m-1}{m}$).

    Bisection

    Bisection is binary search on a sign change: if $f$ is continuous and changes sign on $[a,b]$, the root cannot escape; halve the interval, keep the half with the sign change, repeat. It gains exactly one binary digit per iteration — slow, but with an ironclad guarantee no other method matches.

    Definition Given $f$ continuous with $f(a)f(b) < 0$: set $m = (a+b)/2$; if $f(a)f(m) \le 0$ set $b = m$ else $a = m$. After $k$ steps the bracket has width $(b-a)/2^k$ and always contains a root (IVT). Iterations to tolerance $\tau$: $k = \lceil \log_2\frac{b-a}{\tau}\rceil$.
    Worked example $f(x) = x^3 + x - 1$ on $[0,1]$. $m=0.5$: $f = -0.375 < 0$ → root in $[0.5, 1]$. $m = 0.75$: $f = 0.171875 > 0$ → $[0.5, 0.75]$. $m = 0.625$: $f = -0.130859$ → $[0.625, 0.75]$. $m = 0.6875$: $f = 0.012451$ → $[0.625, 0.6875]$. Four steps: root pinned to width $1/16$; true root $\approx 0.682328$. ✓ in bracket.
    Pitfall Bisection needs a sign change, so it cannot find roots of even multiplicity ($x^2$ touches zero without crossing) and it can be fooled by discontinuities: $f(x) = 1/x$ on $[-1, 1]$ has $f(-1)f(1) < 0$ and no root — bisection converges confidently to the pole at 0. Continuity is a hypothesis, not a decoration. Also compute $m = a + (b-a)/2$, not $(a+b)/2$, to dodge overflow/rounding at extreme magnitudes.

So worst case, $k$ evaluations can only shrink uncertainty by $2^k$: bisection is information-optimal among sign-query methods. Newton beats it only by using more information per query ($f$'s value AND derivative, plus smoothness).

    Newton's method

    Newton's method rides the tangent line: at your current guess, replace $f$ by its linearization and jump to where THAT hits zero. Near a simple root the linearization is nearly perfect, so the error squares each step — six correct digits become twelve. Far from a root, the tangent can fling you anywhere.

    Definition $$x_{k+1} = x_k - \frac{f(x_k)}{f'(x_k)}.$$ If $f$ is $C^2$, $x^*$ is a simple root, and $x_0$ is close enough, convergence is quadratic: $e_{k+1} \approx \frac{|f''(x^*)|}{2|f'(x^*)|}e_k^2$. The secant method replaces $f'(x_k)$ by the finite difference through the last two iterates: order $\varphi \approx 1.618$, one $f$-evaluation per step.
    Worked example $f(x) = x^2 - 2$, $x_0 = 1.5$: iteration $x_{k+1} = \frac{x_k}{2} + \frac{1}{x_k}$ (Heron's rule). $x_1 = 0.75 + 0.6\overline{6} = 1.41\overline{6}$; $x_2 = 0.7083\overline{3} + 0.7058824 = 1.4142157$; $x_3 = 1.4142135624$ — errors: $8.6\times10^{-2} \to 2.5\times10^{-3} \to 2.1\times10^{-6} \to 1.6\times10^{-12}$. Digits double. ✓

    Fixed-point iteration

    Rewrite $f(x)=0$ as $x = g(x)$ and just iterate: $x_{k+1} = g(x_k)$. Whether this spirals into the fixed point or flees it depends on one number: the slope of $g$ there. $|g'| < 1$ contracts, $|g'| > 1$ repels. The Banach fixed-point theorem turns this into the most reusable convergence tool in analysis.

    Theorem (Banach fixed point) If $g:[a,b]\to[a,b]$ is a contraction — $|g(x)-g(y)| \le L|x-y|$ with $L<1$ — then $g$ has a unique fixed point $x^*$ in $[a,b]$, the iteration $x_{k+1}=g(x_k)$ converges to it from ANY start in $[a,b]$, and $|x_k - x^*| \le \frac{L^k}{1-L}|x_1 - x_0|$. If $g$ is differentiable, $L = \max|g'|$ works, and asymptotically $e_{k+1} \approx |g'(x^*)|\,e_k$: linear with rate $|g'(x^*)|$.
    Worked example Solve $x = \cos x$. $g = \cos$: on $[0,1]$, $|g'| = |\sin x| \le \sin 1 \approx 0.841 < 1$: contraction. Iterate from $x_0 = 1$: $1 \to 0.5403 \to 0.8576 \to 0.6543 \to 0.7935 \to 0.7014 \to \cdots \to 0.739085$. Converges, slowly (rate $\sin(0.739) \approx 0.674$: each step multiplies the error by ~0.67, needing ~6 steps per digit). Newton on $\cos x - x$ gets there in 4 steps total.

    Linear system solvers

    Solving $Ax = b$ is the inner loop of scientific computing and of second-order optimization. The menu: direct methods factor $A$ once (LU, QR, Cholesky) and solve exactly-up-to-rounding in predictable time; iterative methods (Jacobi, Gauss–Seidel, conjugate gradient) multiply by $A$ repeatedly and converge, winning when $A$ is huge and sparse.

    Definition Direct: factor $A$ into triangular/orthogonal pieces, then solve by substitution; cost $O(n^3)$ to factor, $O(n^2)$ per extra right-hand side. Iterative: generate $x_k \to A^{-1}b$ using only matvecs ($O(\text{nnz})$ each). A triangular system $Lx = b$ (lower) solves by forward substitution: $x_i = \big(b_i - \sum_{j<i} L_{ij}x_j\big)/L_{ii}$, cost $\sim n^2$ flops.
    Worked example Solve $\begin{pmatrix}2 & 0 & 0\\ 1 & 3 & 0\\ -1 & 2 & 4\end{pmatrix}x = \begin{pmatrix}4\\5\\1\end{pmatrix}$ by forward substitution: $x_1 = 2$; $x_2 = (5 - 1\cdot2)/3 = 1$; $x_3 = (1 - (-1)\cdot2 - 2\cdot1)/4 = 1/4$. Triangular structure makes it a cascade, no elimination needed — which is exactly why factorizations aim at triangles.
    Pitfall Never solve least squares $\min\|Ax-b\|$ by the normal equations $A^\top A x = A^\top b$ when conditioning matters: $\kappa(A^\top A) = \kappa(A)^2$ — you square the amplifier. QR (below) works with $\kappa(A)$ itself.

      Solution
      Back substitution: $x_2 = 2$; $x_1 = (5-1\cdot2)/3 = 1$.

    Gaussian elimination

    Gaussian elimination clears the unknowns column by column: subtract multiples of a pivot row from the rows below until the system is triangular, then back-substitute. It is grade-school equation-juggling made systematic, and with row swaps for safety (partial pivoting) it is the workhorse behind every dense solve().

    Definition For $k = 1..n{-}1$: choose pivot row (partial pivoting: swap up the row with the largest $|a_{ik}|$, guaranteeing multipliers $|m_{ik}|\le1$), then for each $i > k$: $m_{ik} = a_{ik}/a_{kk}$, row$_i \mathrel{-}= m_{ik}\,$row$_k$ (and same to $b$). Cost: $\frac{2}{3}n^3 + O(n^2)$ flops. Then back substitution.
    Worked example $\begin{aligned} 2x + y - z &= 3\\ 4x + y &= 6 \\ -2x + 2y + 2z &= 2\end{aligned}$.     3. HARD Elimination without pivoting breaks on $\begin{pmatrix}0&1\\1&0\end{pmatrix}$ and is unstable for tiny pivots, yet is provably backward stable if $A$ is diagonally dominant or symmetric positive definite. Why do tiny pivots not arise in the SPD case?
      Solution
      For SPD $A$, every leading principal submatrix is SPD, and the pivot at step $k$ equals $\frac{\det A_k}{\det A_{k-1}} > 0$; moreover each elimination step leaves the trailing submatrix SPD (it is a Schur complement, $S = A_{22} - A_{21}A_{11}^{-1}A_{12}$, again SPD), and its diagonal entries — the future pivots — satisfy $0 < s_{ii} \le a_{ii}$: pivots stay positive and bounded, element growth is bounded by 1.     LU decomposition

    LU is Gaussian elimination remembered: the multipliers you used to clear each column, filed into a unit lower-triangular $L$, and the triangle you ended with as $U$. Then $A = LU$, and any future $Ax=b$ is two quick triangular solves. Factor once, solve forever.

    Definition $PA = LU$ with $P$ a permutation (the pivoting row swaps), $L$ unit lower triangular ($L_{ik} = m_{ik}$, ones on the diagonal), $U$ upper triangular. Solve $Ax=b$: permute $Pb$, forward-solve $Ly = Pb$, back-solve $Ux = y$. Determinant for free: $\det A = \pm\prod_i U_{ii}$ (sign from $P$).
    Worked example $A = \begin{pmatrix}2 & 1\\ 6 & 4\end{pmatrix}$ (no pivoting needed): multiplier $m_{21} = 3$; $U = \begin{pmatrix}2 & 1\\ 0 & 1\end{pmatrix}$, $L = \begin{pmatrix}1 & 0\\ 3 & 1\end{pmatrix}$. Check: $LU = \begin{pmatrix}2&1\\6&4\end{pmatrix}$ ✓. Solve $Ax = (4, 14)^\top$: $Ly = b$: $y = (4, 2)^\top$; $Ux = y$: $x_2 = 2$, $x_1 = (4-2)/2 = 1$. Verify: $(2\cdot1+1\cdot2,\ 6+8) = (4,14)$ ✓. And $\det A = 2\cdot1 = 2$ ✓.
    Pitfall Not every invertible matrix has a plain LU ($a_{11}=0$ kills it instantly); with partial pivoting, $PA=LU$ always exists for invertible $A$ and is stable in practice (worst-case element growth $2^{n-1}$ exists but is pathological). Never skip the $P$.

    QR decomposition

    QR writes $A$ as an orthogonal matrix times a triangle: Gram–Schmidt (Ch 8) in matrix clothing. Because orthogonal matrices amplify nothing ($\kappa_2(Q) = 1$), QR is the stable route to least squares — the reason lstsq beats the normal equations.

    Definition For $A \in \mathbb R^{m\times n}$, $m \ge n$, full rank: $A = QR$ with $Q\in\mathbb R^{m\times n}$ having orthonormal columns ($Q^\top Q = I$) and $R\in\mathbb R^{n\times n}$ upper triangular (thin QR). Least squares $\min_x \|Ax - b\|_2$: since $\|Ax-b\|^2 = \|Rx - Q^\top b\|^2 + \|(I - QQ^\top)b\|^2$, the minimizer solves $Rx = Q^\top b$ by back substitution. In practice $Q$ is built from Householder reflections, not classical Gram–Schmidt (which loses orthogonality in floating point; use modified G-S or Householder).
    Worked example $A = \begin{pmatrix}1 & 1\\ 1 & 0 \\ 0 & 1\end{pmatrix}$. G-S: $q_1 = \frac{1}{\sqrt2}(1,1,0)^\top$. $a_2 = (1,0,1)^\top$; $\langle a_2, q_1\rangle = \frac1{\sqrt2}$; residual $a_2 - \frac1{\sqrt2}q_1 = (1,0,1)^\top - (\tfrac12,\tfrac12,0)^\top = (\tfrac12, -\tfrac12, 1)^\top$, norm $\sqrt{\tfrac32} = \frac{\sqrt6}{2}$: $q_2 = \frac1{\sqrt6}(1,-1,2)^\top$. $R = \begin{pmatrix}\sqrt2 & \frac{1}{\sqrt2}\\ 0 & \frac{\sqrt6}{2}\end{pmatrix}$. Check $QR$ col 2: $\frac1{\sqrt2}\cdot\frac1{\sqrt2}(1,1,0)+\frac{\sqrt6}{2}\cdot\frac{1}{\sqrt6}(1,-1,2) = (\tfrac12+\tfrac12, \tfrac12-\tfrac12, 1) = (1,0,1)$ ✓.
    Where this goes QR is the engine of the QR eigenvalue algorithm (below) and the stable core of linear regression (Ch 13, Ch 19).

    Cholesky decomposition

    Symmetric positive definite matrices — covariance matrices, Hessians at minima, kernel matrices — admit a factorization twice as fast as LU and needing no pivoting: $A = LL^\top$, a "square root" of the matrix. If Cholesky fails, your matrix wasn't positive definite; running it is in fact the standard PD test.

    Definition For SPD $A$: $A = LL^\top$ with $L$ lower triangular, $L_{ii} > 0$, unique. Entries: $$L_{jj} = \sqrt{A_{jj} - \sum_{k<j}L_{jk}^2}, \qquad L_{ij} = \frac{A_{ij} - \sum_{k<j}L_{ik}L_{jk}}{L_{jj}}\ (i>j).$$ Cost $\frac13 n^3$ flops — half of LU. Applications: solving SPD systems, sampling $\mathcal N(\mu, \Sigma)$ via $x = \mu + Lz$ with $z\sim\mathcal N(0, I)$, log-determinants $\log\det A = 2\sum_i \log L_{ii}$.
    Worked example $A = \begin{pmatrix}4 & 2\\ 2 & 10\end{pmatrix}$: $L_{11} = 2$; $L_{21} = 2/2 = 1$; $L_{22} = \sqrt{10 - 1} = 3$. $L = \begin{pmatrix}2&0\\1&3\end{pmatrix}$; check $LL^\top = \begin{pmatrix}4&2\\2&10\end{pmatrix}$ ✓. Sample from $\mathcal N(0, A)$: draw $z = (0.5, -1)^\top \Rightarrow x = Lz = (1, -2.5)^\top$; indeed $\mathrm{Cov}(Lz) = L\,I\,L^\top = A$.
    Pitfall Numerically near-singular covariance matrices make $L_{jj}$'s radicand go negative from rounding alone. Standard fix: add jitter $\epsilon I$ ($\epsilon \sim 10^{-6}$·scale) before factoring — every Gaussian-process library does this, and it is a Bayesian prior in disguise.

    Iterative solvers

    When $A$ is a million-by-million sparse matrix, factorizations drown in fill-in; iterative solvers only ever touch $A$ through matrix-vector products. The classical splittings (Jacobi, Gauss–Seidel) polish a guess by cycling through equations; Krylov methods (CG, GMRES) are smarter, building the best answer in a growing subspace of matvec results.

    Definition Split $A = M - N$ with $M$ easy to invert; iterate $Mx_{k+1} = Nx_k + b$, i.e. $x_{k+1} = M^{-1}Nx_k + M^{-1}b$. Converges for every start iff $\rho(M^{-1}N) < 1$ (spectral radius). Jacobi: $M = D$ (diagonal): $x^{new}_i = \frac{1}{a_{ii}}(b_i - \sum_{j\ne i} a_{ij}x_j)$. Gauss–Seidel: $M = $ lower triangle including diagonal — uses updated values immediately. Both converge if $A$ is strictly diagonally dominant; G-S also for SPD $A$.
    Worked example $\begin{pmatrix}4 & 1\\ 2 & 5\end{pmatrix}x = \begin{pmatrix}9\\ 12\end{pmatrix}$ (solution $x = (\frac{33}{18}, \frac{30}{18})\ldots$ compute: from 2nd eq $x_2 = (12-2x_1)/5$; substitute: $4x_1 + \frac{12-2x_1}{5} = 9 \Rightarrow 20x_1 + 12 - 2x_1 = 45 \Rightarrow x_1 = \frac{33}{18} = 1.8\overline3$, $x_2 = \frac{12 - 3.6\overline6}{5} = 1.6\overline6$). Jacobi from $(0,0)$: $x^{(1)} = (\frac94, \frac{12}5) = (2.25, 2.4)$; $x^{(2)} = (\frac{9-2.4}{4}, \frac{12-4.5}{5}) = (1.65, 1.5)$; $x^{(3)} = (\frac{9-1.5}{4}, \frac{12-3.3}{5}) = (1.875, 1.74)$ — pinballing toward $(1.833, 1.667)$, error shrinking ~3× per two sweeps. Gauss–Seidel from $(0,0)$: $x_1 = 2.25$, then $x_2 = (12-4.5)/5 = 1.5$; next sweep $x_1 = (9-1.5)/4 = 1.875$, $x_2 = (12-3.75)/5 = 1.65$ — noticeably faster.

    Conjugate gradient

    For SPD systems, conjugate gradient is the aristocrat of iterative solvers. It reads $Ax = b$ as minimizing the quadratic $\phi(x) = \frac12 x^\top Ax - b^\top x$ and takes steps that are $A$-orthogonal to all previous ones — so it never undoes earlier progress and, in exact arithmetic, finishes in at most $n$ steps. In practice it gets close in far fewer, at one matvec per step.

    Definition CG iterates: $r_0 = b - Ax_0$, $p_0 = r_0$; then $\alpha_k = \frac{r_k^\top r_k}{p_k^\top A p_k}$, $x_{k+1} = x_k + \alpha_k p_k$, $r_{k+1} = r_k - \alpha_k Ap_k$, $\beta_k = \frac{r_{k+1}^\top r_{k+1}}{r_k^\top r_k}$, $p_{k+1} = r_{k+1} + \beta_k p_k$. Convergence: $\|x_k - x^*\|_A \le 2\left(\frac{\sqrt\kappa - 1}{\sqrt\kappa + 1}\right)^k \|x_0 - x^*\|_A$ — the error decays with $\sqrt{\kappa}$, vs $\kappa$ for plain gradient descent. Preconditioning solves $M^{-1}Ax = M^{-1}b$ with $M \approx A$ cheaply invertible, shrinking the effective $\kappa$.
    Worked example $A = \begin{pmatrix}4 & 1\\ 1 & 3\end{pmatrix}$, $b = (1, 2)^\top$, $x_0 = 0$. $r_0 = p_0 = (1,2)^\top$. $Ap_0 = (6, 7)^\top$; $\alpha_0 = \frac{5}{1\cdot6 + 2\cdot7} = \frac5{20} = \frac14$. $x_1 = (0.25, 0.5)$; $r_1 = (1,2) - \frac14(6,7) = (-0.5, 0.25)$. $\beta_0 = \frac{0.3125}{5} = 0.0625$; $p_1 = (-0.5,0.25) + 0.0625(1,2) = (-0.4375, 0.375)$. $Ap_1 = (-1.375, 0.6875)$; $\alpha_1 = \frac{0.3125}{(-0.4375)(-1.375) + 0.375\cdot0.6875} = \frac{0.3125}{0.859375} = \frac{4}{11}$. $x_2 = (0.25 - \frac{4}{11}\cdot0.4375,\ 0.5 + \frac4{11}\cdot 0.375) = (\frac1{11}, \frac{7}{11})$. Check: $Ax_2 = (\frac{4+7}{11}, \frac{1+21}{11}) = (1, 2)$ ✓ — exact in $n = 2$ steps, as promised.
    Where this goes CG's $\sqrt\kappa$ vs GD's $\kappa$ is the same acceleration story as momentum (Ch 15); CG with Hessian-vector products powers "Hessian-free" second-order training and trust-region RL methods (Ch 25).

    Eigenvalue algorithms

    You cannot compute eigenvalues by solving the characteristic polynomial — for $n \ge 5$ no formula exists (Abel), and the polynomial route is numerically disastrous anyway. Real algorithms iterate: power-type methods peel off one eigenpair; the QR algorithm — factor, swap, repeat — converges to all of them and is among the most beautiful ideas in numerical analysis.

    Definition QR algorithm: $A_0 = A$; repeat $A_k = Q_kR_k$ (QR factorization), $A_{k+1} = R_kQ_k$. Each step is a similarity: $A_{k+1} = Q_k^\top A_k Q_k$ — same eigenvalues; under mild conditions $A_k \to$ (quasi-)triangular with the eigenvalues on the diagonal (a Schur form). Practical version: reduce to Hessenberg form first ($O(n^3)$ once, then $O(n^2)$/iteration), add shifts for cubic-in-practice convergence. Symmetric case: tridiagonal + Wilkinson shifts. Total $O(n^3)$.
    Worked example One QR step on $A = \begin{pmatrix}2 & 1\\ 1 & 2\end{pmatrix}$ (eigenvalues 3, 1). QR: columns $(2,1), (1,2)$; $q_1 = \frac1{\sqrt5}(2,1)^\top$; $r_{11} = \sqrt5$, $r_{12} = q_1^\top(1,2) = \frac{4}{\sqrt5}$; residual $(1,2) - \frac45(2,1) = (-\frac35, \frac65)$, $q_2 = \frac1{\sqrt5}(-1,2)^\top$, $r_{22} = \frac{3}{\sqrt5}$. $RQ = \frac15\begin{pmatrix}5 & 4\\ 0 & 3\end{pmatrix}\begin{pmatrix}2 & -1\\ 1 & 2\end{pmatrix} = \frac15\begin{pmatrix}14 & 3\\ 3 & 6\end{pmatrix} = \begin{pmatrix}2.8 & 0.6\\ 0.6 & 1.2\end{pmatrix}$. Diagonal moved from (2,2) toward (3,1); off-diagonal shrank $1 \to 0.6$; trace still 4, det still 3. ✓ A few more sweeps: off-diagonal $\to 0$, diagonal $\to (3,1)$.
    Pitfall Eigenvalues of nonsymmetric matrices can be violently ill-conditioned (a $10^{-10}$ perturbation of a Jordan-ish block moves eigenvalues by $10^{-1}$); symmetric matrices are perfectly conditioned ($|\lambda_i(A+E) - \lambda_i(A)| \le \|E\|_2$, Weyl). Know which case you're in before trusting digits. Never compute eigenvalues via $\det(A - \lambda I)$ root-finding: polynomial coefficients are an unstable intermediate (Wilkinson's polynomial).

    Power iteration

    Multiply a random vector by $A$ again and again: whatever direction $A$ stretches most takes over, exponentially. That is power iteration — three lines of code for the dominant eigenpair, and the mathematical heart of PageRank, of PCA-at-scale, and of spectral-norm estimates in deep learning.

    Definition $v_{k+1} = \frac{Av_k}{\|Av_k\|}$. If $|\lambda_1| > |\lambda_2| \ge \dots$ and $v_0$ has a component along the dominant eigenvector $u_1$, then $v_k \to \pm u_1$ with error $O(|\lambda_2/\lambda_1|^k)$; the Rayleigh quotient $\lambda^{(k)} = v_k^\top A v_k$ (for symmetric $A$) estimates $\lambda_1$ with error $O(|\lambda_2/\lambda_1|^{2k})$. Variants: inverse iteration (apply $(A - \sigma I)^{-1}$: converges to the eigenvalue nearest the shift $\sigma$), Rayleigh-quotient iteration (update the shift each step: cubic convergence), deflation or block/Lanczos methods for several eigenpairs.
    Worked example $A = \begin{pmatrix}2 & 1\\ 1 & 2\end{pmatrix}$ ($\lambda = 3$ at $u_1 = \frac{1}{\sqrt2}(1,1)$; $\lambda_2 = 1$). Start $v_0 = (1, 0)^\top$: $Av_0 = (2,1)$, normalize (÷$\sqrt5$); $A(2,1) = (5, 4)$; $A(5,4) = (14, 13)$; $A(14,13) = (41, 40)$. Direction ratios: $0.5, 0.8, 0.929, 0.976 \to 1$ — the gap $1 - $ratio shrinks by $\lambda_2/\lambda_1 = 1/3$ each step. ✓ Rayleigh quotient at $(14,13)/\|\cdot\|$: $\frac{(14,13)A(14,13)^\top}{14^2+13^2} = \frac{2(196+169) + 2\cdot14\cdot13\cdot\ldots}{365}$ — compute directly: $A(14,13) = (41,40)$, numerator $14\cdot41 + 13\cdot40 = 574+520 = 1094$, so $\lambda \approx 1094/365 = 2.9973$: three digits after 3 multiplications.

    Automatic differentiation

    Automatic differentiation is the third way, neither symbolic nor numerical-approximate: run the program, but propagate derivative information through every elementary operation using the chain rule. The result is EXACT to floating point, costs a small constant times the original program, and needs no formula for the function — just its code. It is the technology that makes deep learning trainable.

    Definition Any numeric program is a composition of primitives (+, ×, exp, sin, …) whose derivatives are known. Autodiff applies the chain rule mechanically across the composition, in one of two orders: forward mode (propagate $\frac{\partial(\text{everything})}{\partial(\text{one input})}$ alongside values) or reverse mode (record the computation, then propagate $\frac{\partial(\text{one output})}{\partial(\text{everything})}$ backward). It is NOT finite differences (no $h$, no truncation error) and NOT symbolic algebra (no expression swell; control flow, loops and branches differentiate for free along the taken path).
    Worked example $f(x) = x\cdot\sin(x^2)$ at $x = 1$: the program computes $a = x^2 = 1$, $b = \sin a = 0.84147$, $f = x b = 0.84147$. True derivative: $f' = \sin(x^2) + 2x^2\cos(x^2) = 0.84147 + 2(0.54030) = 1.92207$. Autodiff (either mode) produces exactly this from the chain rule on the three-step program — no $10^{-8}$ fudge, no symbolic expansion.
    Pitfall Autodiff differentiates the PROGRAM, not the ideal function: abs at 0, relu at 0, branches like if x == 0: return 0 produce subgradient-ish or plain wrong answers at kinks ($\frac{d}{dx}\sqrt{x^2}$ at 0 gives NaN). And $\sqrt{\cdot}$ at 0, division created by the chain rule, can NaN a whole training run through one dead branch — the infamous torch.where NaN-gradient trap.
    Drill
    1. EASY Name the error sources of (a) finite differences, (b) symbolic differentiation, (c) autodiff.
      Solution
      (a) truncation + cancellation ($\sim u^{2/3}$ at best); (b) none numerically, but expression swell makes it infeasible for programs, and it can't handle loops/branches naturally; (c) only ordinary floating-point rounding of the derivative program — machine-precision exact.
    2. MED $f(x,y) = \exp(xy) + y^2$ at $(2, 1)$. Compute $f, \partial f/\partial x, \partial f/\partial y$ as autodiff would (chain rule on primitives).
      Solution
      $t = xy = 2$; $u = e^t = 7.389$; $v = y^2 = 1$; $f = 8.389$. $\partial t = (y, x) = (1, 2)$; $\partial u = e^t\partial t = (7.389, 14.778)$; $\partial v = (0, 2y) = (0,2)$; $\nabla f = (7.389, 16.778)$.
    3. HARD Gradient checking: you verify an autodiff gradient against central differences and see relative disagreement $10^{-3}$ in float32. Bug or expected? What about $10^{-7}$ in float64?
      Solution
      float32: $u \approx 6\times10^{-8}$; central differences achieve $\sim u^{2/3} \approx 10^{-5}$ at the optimal $h$; $10^{-3}$ is 100× worse — suspicious but possible with bad $h$, poor scaling, or a kink nearby; rerun in float64 before declaring a bug. float64 disagreement $10^{-7}$: right at the expected $u^{2/3} \approx 4\times10^{-11}$…? No: $u^{2/3} = (10^{-16})^{2/3} \approx 2\times10^{-11}$, so $10^{-7}$ is 5000× too big — with a good $h$ that's a genuine bug (or a nondifferentiable point). Always check at several random points and use $h \approx 10^{-6}\max(1,|x|)$.

    Forward-mode autodiff

    Forward mode pushes derivatives along with values: every intermediate quantity carries a "tangent" — its sensitivity to one chosen input. The cleanest implementation is dual numbers: compute with $x + \dot x\,\epsilon$ where $\epsilon^2 = 0$, and the $\epsilon$-coefficient of the output IS the derivative. One pass per input direction.

    Definition A dual number is $a + b\epsilon$ with $\epsilon^2 = 0$: $(a + b\epsilon)+(c+d\epsilon) = (a+c)+(b+d)\epsilon$; $(a+b\epsilon)(c+d\epsilon) = ac + (ad+bc)\epsilon$; $f(a + b\epsilon) = f(a) + f'(a)b\,\epsilon$ for smooth primitives. Seeding input $x_i$ with tangent 1 (others 0) and running the program yields $\frac{\partial f}{\partial x_i}$ for every output. Cost: one forward pass per input direction — a full gradient of $f:\mathbb R^n \to \mathbb R$ costs $n$ passes; a full Jacobian column ($Jv$, a JVP) costs one.
    Worked example $f(x) = \frac{x^2 + 1}{x}$ at $x = 2$, seed $\dot x = 1$: compute with $2 + \epsilon$. $x^2 = 4 + 4\epsilon$; $+1$: $5 + 4\epsilon$; divide by $2 + \epsilon$: $\frac{5+4\epsilon}{2+\epsilon} = (5+4\epsilon)\cdot\frac12(1 - \frac\epsilon2) = \frac52 + (2 - \frac54)\epsilon = 2.5 + 0.75\epsilon$. So $f(2) = 2.5$, $f'(2) = 0.75$. Check: $f' = 1 - x^{-2} = 1 - \frac14 = 0.75$ ✓.
    Think first A network has $n = 10^9$ parameters and one scalar loss. How many forward-mode passes for the full gradient? Reverse-mode passes?
    Reveal
    Forward: $10^9$ passes (one per parameter) — years of compute. Reverse: ONE backward pass, cost a small multiple of the forward pass. The shape $\mathbb R^{10^9}\to\mathbb R$ is maximally reverse-friendly; that asymmetry is why backprop won. Forward mode wins in the transposed case ($\mathbb R\to\mathbb R^m$) and for Hessian-vector products (forward-over-reverse).
    Drill
    1. EASY Using dual numbers, differentiate $f(x) = x^3$ at $x = 2$.
      Solution
      $(2+\epsilon)^3 = 8 + 3\cdot4\epsilon = 8 + 12\epsilon$ ($\epsilon^2$ terms vanish): $f' = 12$ ✓.
    2. MED Derive the dual-number rule for division: $(a + b\epsilon)/(c + d\epsilon)$.
      Solution
      Multiply by $\frac{c - d\epsilon}{c - d\epsilon}$: numerator $(ac + (bc - ad)\epsilon)$, denominator $c^2$ ($\epsilon^2 = 0$): $\frac ac + \frac{bc - ad}{c^2}\epsilon$ — exactly the quotient rule.
    3. HARD $f(x, y) = \sin(xy) + x^2$: compute the directional derivative (JVP) along $v = (1, 2)$ at $(x,y) = (1, \pi)$ with ONE forward pass.
      Solution
      Seed $\dot x = 1, \dot y = 2$. $t = xy = \pi$, $\dot t = \dot x y + x\dot y = \pi + 2$. $s = \sin t = 0$, $\dot s = \cos(\pi)\dot t = -(\pi + 2)$. $u = x^2 = 1$, $\dot u = 2$. $f = 1$, $\dot f = 2 - \pi - 2 = -\pi$. Check: $\nabla f = (y\cos(xy) + 2x,\ x\cos(xy)) = (-\pi + 2, -1)$; $\nabla f\cdot v = -\pi + 2 - 2 = -\pi$ ✓.

    Reverse-mode autodiff

    Reverse mode runs the movie backward: first execute the program and remember every intermediate, then sweep from the output to the inputs, asking each step "how much did you influence the loss?" One backward sweep prices the influence of EVERY input simultaneously — the whole gradient for the cost of a few forward passes. Backpropagation is precisely this, applied to neural network losses.

    Definition For each intermediate $v_i$, define the adjoint $\bar v_i = \frac{\partial f}{\partial v_i}$. Initialize $\bar f = 1$; process nodes in reverse topological order, and for each operation $v_k = \phi(v_{i_1}, \dots)$ accumulate into its parents: $\bar v_{i_j} \mathrel{+}= \bar v_k\,\frac{\partial \phi}{\partial v_{i_j}}$. One reverse sweep yields $\nabla_x f$ for scalar $f$ at cost $\le c\times$(forward cost), $c \approx 2\text{–}3$ in flops — but requires storing (or recomputing: checkpointing) the forward intermediates. Computes vector-Jacobian products $v^\top J$ (VJPs) in general.
    Worked example $f = (x + y)\, x y$ at $x = 2, y = 3$. Forward: $a = x + y = 5$; $b = xy = 6$; $f = ab = 30$. Backward: $\bar f = 1$. $f = ab$: $\bar a = b = 6$, $\bar b = a = 5$. $b = xy$: $\bar x \mathrel{+}= \bar b\,y = 15$, $\bar y \mathrel{+}= \bar b\,x = 10$. $a = x + y$: $\bar x \mathrel{+}= \bar a = 6 \Rightarrow \bar x = 21$; $\bar y \mathrel{+}= 6 \Rightarrow \bar y = 16$. Check symbolically: $f = x^2y + xy^2$, $f_x = 2xy + y^2 = 12 + 9 = 21$ ✓, $f_y = x^2 + 2xy = 4 + 12 = 16$ ✓. Note the $\mathrel{+}=$: $x$ influences $f$ through two paths, and adjoints ADD across paths.
    Pitfall Forgetting that adjoints accumulate over fan-out is the classic hand-rolled-backprop bug (variables reused in two places get half their gradient). The other cost trap: reverse mode's memory is proportional to the forward computation's length — hence gradient checkpointing, which stores every $\sqrt T$-th activation and recomputes the rest, trading ~30% compute for ~$\sqrt T$ memory.
    Where this goes Reverse mode over a network's computational graph IS backpropagation — Ch 9 set up the chain rule; Ch 21 applies this machinery layer by layer; Ch 23's training systems checkpoint and shard exactly these intermediates.
    Drill
    1. EASY Reverse-differentiate $f = \sin(x) + x$ at $x = 0$.
      Solution
      Forward: $s = \sin x = 0$, $f = s + x = 0$. Backward: $\bar s = 1$, $\bar x = \bar s\cos(0) + 1 = 2$. ($f' = \cos x + 1 = 2$ ✓.)
    2. MED $f = \exp(u)$, $u = x^2 + y^2$, at $(1, 2)$: run the reverse sweep.
      Solution
      Forward: $u = 5$, $f = e^5 \approx 148.41$. Backward: $\bar u = e^5$; $\bar x = \bar u\cdot 2x = 2e^5 \approx 296.8$; $\bar y = \bar u\cdot 2y = 4e^5 \approx 593.7$. One sweep, both partials.
    3. HARD Derive the backward rule for matrix multiplication $C = AB$: given $\bar C = \frac{\partial f}{\partial C}$, find $\bar A, \bar B$.
      Solution
      $f$'s differential: $df = \langle \bar C, dC\rangle = \mathrm{tr}(\bar C^\top(dA\,B + A\,dB)) = \mathrm{tr}((B\bar C^\top)dA) + \mathrm{tr}((\bar C^\top A)dB)$. Matching $df = \langle\bar A, dA\rangle + \langle \bar B, dB\rangle$: $\bar A = \bar C B^\top$, $\bar B = A^\top\bar C$. Sanity: shapes $(m{\times}p) = (m{\times}n)(n{\times}p)^{...}$ — with $A: m{\times}k$, $B: k{\times}n$: $\bar A = \bar C B^\top$ is $(m{\times}n)(n{\times}k) = m\times k$ ✓. These two formulas ARE the backward pass of every linear layer.

    Computational graphs

    A computational graph makes a program's dataflow explicit: nodes are operations, edges carry values, and the whole thing is a DAG (Ch 17). Forward evaluation is a topological-order sweep; reverse-mode autodiff is the same sweep backward. Frameworks differ mainly in when they build this graph: ahead of time (static — XLA, TorchScript) or as the code runs (dynamic tape — PyTorch eager, JAX tracing).

    Definition A computational graph for $f$ is a DAG whose leaves are inputs/constants and whose internal nodes are primitive ops; each node's value is a function of its parents'. Evaluation: any topological order. Reverse sweep: reverse topological order, adjoint accumulation along every edge: $\bar v_i = \sum_{k:\ i \to k} \bar v_k\,\frac{\partial v_k}{\partial v_i}$ — a sum over paths when unrolled, computed efficiently by sharing. The graph also drives optimization (fusion, common-subexpression elimination) and parallel scheduling.
    Worked example $f(x) = \mathrm{sigmoid}(wx + b)$ as a graph: $x, w, b \to m = wx \to s = m + b \to y = \sigma(s)$. Forward at $w=2, x=1, b=-1$: $m=2$, $s=1$, $y = \sigma(1) = 0.7311$. Reverse with $\bar y = 1$: $\bar s = \sigma(1)(1-\sigma(1)) = 0.7311\times0.2689 = 0.1966$; $\bar b = 0.1966$; $\bar m = 0.1966$; $\bar w = \bar m\,x = 0.1966$; $\bar x = \bar m\,w = 0.3932$. Every deep learning framework does exactly this, node by node, a billion nodes at a time.
    Think first Count paths: in a chain of $L$ layers where each layer's output feeds the next, how many terms does the unrolled chain rule have? What if each layer ALSO has a skip connection to the output?
    Reveal
    A chain has one path: the chain rule is a single product of $L$ Jacobians. With skip connections, paths multiply: each layer either participates or is skipped, giving up to $2^{L}$-ish paths (ResNets as "ensembles of paths") — yet reverse mode still computes the total in $O(L)$ by summing adjoints at each merge node. Dynamic programming over the DAG beats path enumeration exponentially.
    Drill
    1. EASY Draw (describe) the graph of $f = (x+y)^2$ and give one valid evaluation order and its reverse.
      Solution
      $x, y \to a = x+y \to f = a^2$. Forward: $a$, then $f$. Reverse: $\bar f = 1 \to \bar a = 2a \to \bar x = \bar y = 2a = 2(x+y)$.
    2. MED Why must the graph be a DAG for a single forward pass to be well-defined, and how do RNNs (which look cyclic) fit?
      Solution
      A cycle means a value depends on itself with no base case: no topological order, no evaluation. RNNs are cyclic only as a diagram shorthand; training UNROLLS them through time into a DAG (a copy per timestep, shared weights) — backprop-through-time is reverse mode on the unrolled DAG, with adjoints of the shared weights summed across copies.
    3. HARD Node $s$ is used by $k$ downstream nodes. Show its adjoint requires $k$ accumulations, and relate to why y = x; z = x then $f(y, z)$ gives $\bar x = \bar y + \bar z$ — then explain what goes wrong with in-place mutation of $x$ after it was used.
      Solution
      $f$ depends on $s$ through each consumer: $\bar s = \sum_{j=1}^k \bar c_j \frac{\partial c_j}{\partial s}$ — the multivariate chain rule over fan-out; aliasing a variable is fan-out with identity Jacobians, so $\bar x = \bar y + \bar z$. In-place mutation breaks the tape: the backward rule for a consumer of the OLD value needs that old value, but memory now holds the new one — the framework either errors ("a variable needed for gradient computation has been modified by an inplace operation") or silently produces wrong gradients if it can't detect it. The graph abstraction assumes values are immutable once produced.

    Task 2 — Solver bake-off. Implement Gaussian elimination with partial pivoting, Cholesky, and conjugate gradient from scratch; verify all three on a random SPD system against np.linalg.solve, and plot (print) CG's residual decay for a well- vs ill-conditioned matrix.

    Reference solution
    import numpy as np

def lu_pp_solve(A, b):
    A = A.astype(float).copy(); b = b.astype(float).copy(); n = len(b)
    for k in range(n - 1):
        p = k + np.argmax(np.abs(A[k:, k]))
        A[[k, p]], b[[k, p]] = A[[p, k]], b[[p, k]]
        for i in range(k + 1, n):
            m = A[i, k] / A[k, k]
            A[i, k:] -= m * A[k, k:]; b[i] -= m * b[k]
    x = np.zeros(n)
    for i in range(n - 1, -1, -1):
        x[i] = (b[i] - A[i, i+1:] @ x[i+1:]) / A[i, i]
    return x

def cholesky(A):
    n = len(A); L = np.zeros_like(A, dtype=float)
    for j in range(n):
        L[j, j] = np.sqrt(A[j, j] - L[j, :j] @ L[j, :j])
        for i in range(j + 1, n):
            L[i, j] = (A[i, j] - L[i, :j] @ L[j, :j]) / L[j, j]
    return L

def chol_solve(A, b):
    L = cholesky(A)
    y = np.zeros_like(b, dtype=float)
    for i in range(len(b)): y[i] = (b[i] - L[i, :i] @ y[:i]) / L[i, i]
    x = np.zeros_like(b, dtype=float)
    for i in range(len(b) - 1, -1, -1):
        x[i] = (y[i] - L[i+1:, i] @ x[i+1:]) / L[i, i]
    return x

def cg(A, b, tol=1e-10, log=None):
    x = np.zeros_like(b, dtype=float); r = b - A @ x; p = r.copy()
    rs = r @ r
    for k in range(len(b) * 10):
        Ap = A @ p; alpha = rs / (p @ Ap)
        x += alpha * p; r -= alpha * Ap
        rs_new = r @ r
        if log is not None: log.append(np.sqrt(rs_new))
        if np.sqrt(rs_new) < tol: break
        p = r + (rs_new / rs) * p; rs = rs_new
    return x

rng = np.random.default_rng(0)
M = rng.standard_normal((60, 60)); A = M @ M.T + 60 * np.eye(60)
b = rng.standard_normal(60); xref = np.linalg.solve(A, b)
for name, x in [("LU", lu_pp_solve(A, b)), ("Chol", chol_solve(A, b)), ("CG", cg(A, b))]:
    print(name, np.max(np.abs(x - xref)))   # all ~1e-12 or better

for cond in (10, 1e6):                       # conditioning vs CG speed
    d = np.linspace(1, cond, 60); Ad = np.diag(d); log = []
    cg(Ad, np.ones(60), log=log)
    print(f"kappa={cond:.0e}: {len(log)} iters, final residual {log[-1]:.1e}")

class Value:
    def __init__(self, data, children=(), op=''):
        self.data = data; self.grad = 0.0
        self._backward = lambda: None; self._prev = set(children)
    def __add__(self, o):
        o = o if isinstance(o, Value) else Value(o)
        out = Value(self.data + o.data, (self, o), '+')
        def _b(): self.grad += out.grad; o.grad += out.grad
        out._backward = _b; return out
    def __mul__(self, o):
        o = o if isinstance(o, Value) else Value(o)
        out = Value(self.data * o.data, (self, o), '*')
        def _b(): self.grad += o.data * out.grad; o.grad += self.data * out.grad
        out._backward = _b; return out
    def tanh(self):
        t = math.tanh(self.data); out = Value(t, (self,), 'tanh')
        def _b(): self.grad += (1 - t * t) * out.grad
        out._backward = _b; return out
    def exp(self):
        e = math.exp(self.data); out = Value(e, (self,), 'exp')
        def _b(): self.grad += e * out.grad
        out._backward = _b; return out
    def backward(self):
        topo, seen = [], set()
        def build(v):
            if v not in seen:
                seen.add(v)
                for c in v._prev: build(c)
                topo.append(v)
        build(self); self.grad = 1.0
        for v in reversed(topo): v._backward()

def f(a, b): return (a * b + a.tanh()) * b.exp()

a, b = Value(0.5), Value(-1.2)
y = f(a, b); y.backward()
print("autodiff:", a.grad, b.grad)
