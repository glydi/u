    Generalization

    Generalization is the whole game: performing well on inputs you were not trained on. Everything called "intelligence" in this book is a species of it — recognizing a new cat, solving a novel problem, acting in an unseen situation. The deep question of AGI is not "can it fit data" (memorization does that) but "how far, and how reliably, does competence extend beyond the training set."

    Definition For a learned predictor $f$, training distribution $D$, and deployment distribution $D'$, the generalization gap is $\mathbb E_{D'}[\ell(f)] - \mathbb E_{D}[\ell(f)]$. In-distribution generalization ($D' = D$, held-out sample) is bounded by statistical learning theory (Ch 20); out-of-distribution generalization ($D' \ne D$) has no free guarantee and depends on structural assumptions relating $D'$ to $D$ (shared features, invariances, compositional structure).
    Worked example Two models both reach 99% on a held-out MNIST digit sample (in-distribution generalization). Deploy on digits written with a thick brush (a covariate shift): model A drops to 60%, model B holds 95%. Same in-distribution score, wildly different OOD generalization — because B learned stroke topology (invariant to thickness) while A leaned on pixel statistics (thickness-dependent). In-distribution accuracy could not have told them apart; the extrapolation direction is what separates them, and nothing in the training set measured it. AGI-relevant generalization is precisely this untested-direction robustness.
    Where this goes Transfer, compositionality, and few/zero-shot learning (this chapter) are named regimes of OOD generalization; the manifold hypothesis (Ch 9) and representation learning (below) are the structural assumptions that make it possible at all.
    Drill
    1. EASY Why does a low in-distribution generalization gap say nothing about OOD performance?
      Solution
      The in-distribution gap is bounded using i.i.d. samples from $D$; when $D' \ne D$, held-out data from $D$ never probed the region $D'$ lives in. No amount of $D$-sampling constrains behavior where the model was never tested — OOD needs an assumption linking $D'$ to $D$, not more $D$-data.
    2. MED A model has training error 2%, test error (same distribution) 3%, and error under a known shift 40%. Decompose the 40% into parts and say which part learning theory can bound.
      Solution
      Shift error 40% = training error (2%) + in-distribution generalization gap (1%) + OOD gap (37%). Learning theory (Ch 20, uniform convergence) bounds the middle term (1%) via sample size and capacity; the 37% OOD term is outside its scope and requires distributional assumptions (bounded shift, shared invariant features) to control.
    3. HARD Formalize "generality" as generalization across a distribution over tasks and explain why it turns a single number into a spectrum.
      Solution
      Let there be a distribution $\mathcal T$ over tasks $t$, each with its own data distribution $D_t$ and loss. A general system minimizes $\mathbb E_{t \sim \mathcal T}[\text{gap}(f, t)]$. This makes "generalization" relative to $\mathcal T$: performance is a profile over the task space, not a scalar. A system can generalize superbly on $\mathcal T_1$ (say, text tasks) and fail on $\mathcal T_2$ (physical manipulation), so "how general" is meaningless without naming the reference task distribution — which is exactly the difficulty that generality measurement (later) confronts. It also connects to no-free-lunch (Ch 20): averaged over all task distributions no learner is special, so real generality is always claim about a structured, natural $\mathcal T$, not the uniform one.

    Transfer learning

    Transfer learning is reusing what was learned on one task to do better on another — the reason you don't relearn vision every time you learn a new object. The bet: tasks share structure (features, sub-skills, causal mechanisms), so knowledge acquired once amortizes across many. Pretraining-then-finetuning, the dominant paradigm of Ch 21–23, is transfer learning at civilization scale.

    Definition Given a source task $S$ and target task $T$, transfer measures the benefit of $S$-training on $T$-performance: positive transfer if learning $S$ improves $T$ (fewer target samples, higher accuracy, faster convergence), negative transfer if it hurts. Formally, compare target performance of a model pretrained on $S$ then adapted, versus trained on $T$ from scratch, at matched target-data budgets. The transferable object may be features (representations), parameters (initialization), or knowledge (facts, skills).
    Worked example Sample-efficiency curve: training a classifier from scratch needs, say, 10,000 labeled target examples to reach 90%. Initializing from an ImageNet-pretrained backbone reaches 90% with 500 — a 20× data reduction, the signature of positive transfer. The mechanism: the pretrained features (edges, textures, parts) are reused, so target training only fits the last layers. Negative-transfer counterexample: pretraining on line-drawings then transferring to photographs of the same objects can hurt if the low-level features (which dominate the initialization) are mismatched, and the model must first unlearn them — worse than random init.
    Think first Why does transfer help more when the target task has little data than when it has abundant data?
    Reveal
    With abundant target data the model can learn good features from scratch, so the pretrained initialization's advantage washes out (and its biases may even hurt). With scarce target data, the target signal cannot support learning good representations, so borrowing them from the source is the difference between working and not. Transfer is a prior; priors matter most exactly when the likelihood (data) is weak — the Bayesian reading of Ch 13.
    Drill
    1. EASY Name the three things that can transfer between tasks, with an example of each.
      Solution
      Features/representations (ImageNet edges reused for medical imaging); parameters/initialization (a pretrained LLM finetuned for a domain); knowledge/facts (a model that learned physics facts answering new physics questions). Often all three transfer together.
    2. MED Under what condition on source and target does transfer help, stated in terms of shared optimal features?
      Solution
      Transfer helps when the target's optimal predictor is well-approximated using features that are (a) learnable from the source and (b) close to the source's learned features. If the tasks' optimal representations overlap substantially, source training pre-fits the shared part, leaving less for the target to learn; if the optimal representations are near-orthogonal (or worse, conflicting), the shared initialization is a liability — negative transfer. Formally: transfer benefit correlates with the alignment between the source and target's relevant feature subspaces.
    3. HARD Why is large-scale self-supervised pretraining such an effective transfer source, connecting to representation learning and the manifold hypothesis (Ch 9)?
      Solution
      Self-supervised objectives (next-token prediction, masked reconstruction, contrastive) force the model to model the data-generating structure — the low-dimensional manifold on which natural data lies (Ch 9's manifold hypothesis) — because predicting held-out parts requires capturing the regularities that relate parts. That structure is shared across a huge range of downstream tasks (the same objects, syntax, physics, causal relations recur), so the learned representation is a near-universal feature basis for the natural-data manifold. The scale argument: bigger models + more data resolve finer manifold structure, and downstream tasks are (largely) linear-ish readouts on that structure — hence the empirical fact that pretraining loss predicts downstream transfer. The limit of transfer is set by whether the target task lives on the same manifold the pretraining data explored; genuinely novel structure (new physics, new modality) transfers poorly, which is why multimodal and embodied pretraining expand the manifold coverage.

    Compositionality

    Compositionality is the property that the meaning of a whole is built from the meanings of its parts and the rules combining them — the reason you understand "the purple elephant juggling calculus" though you've never seen it. It is the engine of infinite productivity from finite means, and the sharpest current dividing line between systems that memorize and systems that genuinely generalize.

    Definition A representation or function is compositional if there is a homomorphism from the structure of inputs to the structure of outputs: $f(\text{combine}(a, b)) = \text{combine}'(f(a), f(b))$ for the relevant composition operators. Systematic generalization is the observable consequence: having learned the parts (primitives) and some combinations, the system handles novel combinations of known parts correctly.
    Worked example The SCAN benchmark: commands like "jump", "walk twice", "jump left" map to action sequences. Compositional structure: "twice" means repeat, "left" means turn-then-act, and these compose. Test: train on "jump", "walk twice", "walk left"; hold out "jump twice" (a novel combination of known primitives). A memorizing model fails — it never saw "jump" with "twice". A compositional learner produces JUMP JUMP because it factored "twice" as an operator independent of its argument. Empirically, standard sequence models struggle with exactly this held-out-combination split while acing random splits — revealing they interpolate rather than compose. The gap between random-split accuracy and compositional-split accuracy is a measurement of compositionality.
    Pitfall High benchmark scores on random train/test splits can entirely hide a failure of compositionality: if novel combinations appear in both train and test (random split), memorization suffices. Measuring compositionality requires systematic splits that hold out combinations, not just examples — a lesson that generalizes to all of AGI evaluation (below): the split defines what you measure.
    Drill
    1. EASY Why does compositionality give "infinite use of finite means"?
      Solution
      A finite set of primitives plus finite combination rules generates unboundedly many valid wholes (like grammar generating infinite sentences). A system that composes needs only to learn the parts and rules, then handles the combinatorial explosion of combinations for free — the alternative, enumerating combinations, is infinite.
    2. MED Design a systematic (compositional) train/test split for arithmetic word problems and explain what a random split would miss.
      Solution
      Primitives: operations (add, multiply), magnitudes, framings. Systematic split: train on {add small, multiply small, add large} and hold out {multiply large} — a novel combination of a known operation with a known magnitude regime. Also hold out novel operation-count compositions (2-step problems where each step-type was seen alone). A random split would scatter "multiply large" problems into both train and test, so memorized templates suffice and the test never probes whether "multiply" was learned as an operator that composes with "large" — inflating apparent generalization.
    3. HARD Transformers do exhibit some compositional generalization (and it improves with scale and certain data distributions). Reconcile this with the SCAN failures, and state what determines whether composition emerges.
      Solution
      Reconciliation: compositional behavior is not architecturally guaranteed but is learnable, and whether it emerges depends on the training distribution's structure and scale, not just the model. Determinants: (1) Data diversity — if primitives appear in many varied combinations during training, gradient descent is pushed toward a factored representation (the compositional solution generalizes to the training diversity more cheaply than memorization); sparse/skewed combination coverage lets memorization win (the SCAN failure). (2) Scale — larger models and more data expand the combination coverage and the capacity to represent operators, and in-context learning lets models compose at inference from few examples. (3) Format — chain-of-thought and explicit intermediate structure convert a hard one-shot composition into a sequence of simple steps, each in-distribution (the reason CoT helps compositional tasks, Ch 30). So composition is an emergent property of {data structure × scale × inference-time procedure}, which is why the same architecture composes on one distribution and memorizes on another — and why measuring it requires controlling the data's combinatorial structure, not just the model.

    Continual learning

    Real intelligence learns across a lifetime, accumulating skills without a training/deployment boundary. Continual (lifelong) learning studies systems that learn from a stream of tasks or data, integrating the new without a full retrain — and its central obstacle is that naive gradient learning, faced with new data, tends to overwrite the old.

    Definition A continual learner sees a sequence of tasks/distributions $D_1, D_2, \dots$ (often without task boundaries or the ability to revisit past data) and must maintain performance across all seen so far. The core tension is the stability–plasticity dilemma: plasticity (adapt to $D_t$) fights stability (retain $D_{1..t-1}$). Metrics: average accuracy over all seen tasks, backward transfer (effect of new learning on old tasks — negative = forgetting), and forward transfer (effect of old learning on new tasks).
    Worked example Train a network on Task A (classify cats vs dogs) to 95%, then train it only on Task B (cars vs trucks) to 95%. Re-test Task A: accuracy collapses to ~55% — the Task-B gradients moved the shared weights to a Task-B optimum, overwriting Task A. This is catastrophic forgetting (next topic), quantified as backward transfer $= 55\% - 95\% = -40\%$. Contrast a continual method (e.g. replaying a small buffer of Task-A examples during Task-B training): Task A holds at ~90%, backward transfer $\approx -5\%$, at the cost of storing/replaying old data. The number that matters is the whole-history average, not the latest task's score.
    Where this goes Catastrophic forgetting (next) is the failure mode; meta-learning (below) offers learning procedures that are inherently less destructive; and continual learning is a prerequisite for the autonomy and open-ended learning that later topics require.
    Drill
    1. EASY State the stability–plasticity dilemma and why you can't trivially maximize both.
      Solution
      Stability = retain old knowledge; plasticity = absorb new. They conflict because the same parameters encode both: adjusting weights to fit new data moves them off the old data's optimum. Perfect stability (freeze weights) blocks learning; perfect plasticity (fit each new task freely) erases the past. A continual learner must trade or cleverly separate the two.
    2. MED Three method families fight forgetting: replay, regularization, and architectural. Give the core idea and one cost of each.
      Solution
      Replay: store/generate past examples and mix them into current training — cost: memory and privacy of stored data, and generative replay's fidelity. Regularization (e.g. EWC): penalize changing weights important to old tasks (weighted by estimated importance) — cost: importance estimates degrade over long sequences, and the penalty limits plasticity. Architectural: allocate new capacity per task (masks, adapters, growing networks) — cost: parameter growth and needing task identity to route. All three trade one resource (memory, plasticity, parameters) to buy stability.
    3. HARD Elastic Weight Consolidation adds a penalty $\sum_i \frac{\lambda}{2} F_i (\theta_i - \theta_i^*)^2$ when learning a new task, where $\theta^*$ are old-task weights and $F_i$ the Fisher information. Derive why the Fisher weighting is the right importance measure.
      Solution
      Bayesian view: after task A, the posterior over weights $p(\theta \mid D_A)$ encodes what A determined. Learning B should find weights probable under B while staying probable under the A-posterior — i.e. maximize $\log p(D_B \mid \theta) + \log p(\theta \mid D_A)$. Approximate the A-posterior as Gaussian around the MAP $\theta^*$ (Laplace approximation, Ch 13): $\log p(\theta \mid D_A) \approx -\tfrac12 (\theta - \theta^*)^\top H (\theta - \theta^*)$ where $H$ is the Hessian of the negative log-likelihood at $\theta^*$. The Fisher information matrix equals that Hessian in expectation at the optimum (both measure the loss's curvature / how sharply the likelihood constrains each direction), and EWC uses its diagonal $F_i$ for tractability. So $F_i$ measures how much task A's loss cares about $\theta_i$: high $F_i$ = a sharp direction A pinned down (moving it costs A dearly, penalize hard); low $F_i$ = a flat direction A left free (safe to repurpose for B). The penalty is exactly the second-order term of the old task's log-posterior — forgetting is fought by respecting the curvature of what was learned. Limitations follow directly: the Gaussian/diagonal approximation degrades over many tasks and ignores parameter correlations, which is why EWC alone doesn't fully solve long sequences.

    Catastrophic forgetting

    The signature failure of neural continual learning: training on new data doesn't gently add to old knowledge, it abruptly destroys it. The name captures the abruptness — performance on old tasks doesn't decay gracefully, it collapses. Understanding why reveals something fundamental about how distributed representations store information.

    Definition Catastrophic forgetting is a large, rapid drop in performance on previously learned tasks caused by training on new tasks, without revisiting old data. It arises because gradient descent on the new task's loss moves shared parameters toward the new optimum with no term preserving the old — the old knowledge, being distributed across the same weights that the new task overwrites, has no protected storage.
    Worked example Geometric picture with two tasks sharing a weight $w$: Task A's loss is minimized near $w = 2$ (a parabola centered there); Task B's near $w = -3$. Train A: $w \to 2$. Train B (A's loss no longer in the objective): $w \to -3$, and A's loss, evaluated at $w = -3$, is now huge — A is forgotten. The joint optimum minimizing $L_A + L_B$ sits between (weighted by curvatures), say $w = -0.5$ — reachable only if both losses are present. Forgetting is what happens when the objective forgets to include the old loss; every fix (replay, EWC, freezing) is a way to keep a shadow of $L_A$ in the objective while training B.
    Explore

    Two quadratic task-losses share one weight. Train on A then B and watch the weight slide to B's optimum, spiking A's loss. Add an EWC penalty (importance slider) to anchor near A and find the compromise.

    Drill
    1. EASY Why is it called "catastrophic" rather than "gradual"?
      Solution
      Because performance on the old task can collapse after even a little training on the new one — a sharp cliff, not a slow slope — since gradient descent moves shared weights directly toward the new optimum with nothing holding the old.
    2. MED Two tasks share weight $w$; $L_A(w) = (w-2)^2$, $L_B(w) = 3(w+3)^2$. Find the joint minimum and explain why it's closer to B's optimum.
      Solution
      Minimize $L_A + L_B$: derivative $2(w-2) + 6(w+3) = 0 \Rightarrow 8w + 14 = 0 \Rightarrow w = -1.75$. Closer to B's optimum ($-3$) than A's ($2$) because B's loss has higher curvature (coefficient 3 vs 1) — it "pulls harder." This is exactly the Fisher-weighted compromise EWC approximates: the sharper (more informative) task dominates the shared parameter.
    3. HARD Large pretrained models forget less than small ones when finetuned. Give two mechanisms and connect to the loss landscape and overparameterization.
      Solution
      (1) Room in weight space: overparameterized models have high-dimensional, connected low-loss manifolds (flat valleys, cf. Ch 15/21 flat minima). A new task can often be fit by moving along the old task's low-loss manifold rather than off it — there exist directions that improve B while barely changing $L_A$, and gradient descent in a wide model is more likely to find them. Small models have no such slack: every direction that helps B hurts A. (2) Feature reuse over feature rewriting: a large pretrained model already has rich, general features (transfer topic above), so a new task is learned by re-weighting existing features (small changes to a few parameters, e.g. what LoRA exploits) rather than learning new features (large changes to many), and small changes forget less. Both mechanisms say the same thing geometrically: overparameterization creates enough flat, shared low-loss volume that new tasks can be accommodated near the old solution — capacity buys stability for free, which is one reason scale mitigates (without solving) catastrophic forgetting, and why parameter-efficient finetuning is naturally forgetting-resistant.

    Meta-learning

    Meta-learning is learning to learn: instead of learning one task, the system learns a procedure or initialization that makes learning new tasks fast. If ordinary learning fits parameters to data, meta-learning fits the learning process to a distribution of tasks — so that a few examples of any new task from that distribution suffice. It reframes generalization from "across examples" to "across tasks."

    Definition Given a distribution over tasks $p(\mathcal T)$, each task providing a small support set (for adaptation) and query set (for evaluation), meta-learning finds meta-parameters $\phi$ minimizing expected query loss after task-specific adaptation: $\min_\phi \mathbb E_{\mathcal T}\big[ L_{\mathcal T}^{\text{query}}(\text{Adapt}(\phi, \mathcal T^{\text{support}})) \big]$. In MAML, $\phi$ is an initialization and Adapt is a few gradient steps; in metric-based methods, $\phi$ is an embedding and Adapt is nearest-neighbor in it; in black-box methods, a recurrent/attention model reads the support set and predicts.
    Worked example MAML in one step. Tasks are sine regressions $y = a\sin(x + b)$ with random amplitude/phase. Meta-goal: an initialization $\theta$ such that one gradient step on a task's 5 support points nails that task. Inner loop: $\theta'_{\mathcal T} = \theta - \alpha \nabla_\theta L_{\mathcal T}^{\text{support}}(\theta)$. Outer loop: update $\theta$ to reduce $L_{\mathcal T}^{\text{query}}(\theta'_{\mathcal T})$ — i.e. differentiate through the inner step (a gradient of a gradient, Ch 9). The learned $\theta$ sits at a point in weight space from which every sine task is one step away — not good at any task initially, but optimally poised to adapt. Test: a brand-new phase, 5 points, one step → accurate fit, where training-from-scratch on 5 points would badly overfit.
    Think first In what sense is a large language model doing in-context learning already a meta-learner?
    Reveal
    Pretraining on a huge diversity of implicit "tasks" (each document/context poses a prediction problem) is an outer loop; the model learns weights such that conditioning on a prompt's examples (the support set, in context) adapts its behavior to the task without weight updates — the forward pass is the Adapt procedure. This is black-box meta-learning: the "learning algorithm" for new tasks is implemented inside the network's activations. It's why few-shot prompting works at all, and it reframes in-context learning as meta-learning that emerged from scale (Ch 21/23).
    Drill
    1. EASY Distinguish the inner loop from the outer loop in meta-learning.
      Solution
      Inner loop: adapt to a specific task using its support set (fast, few steps or a forward pass). Outer loop: update the meta-parameters across many tasks so that inner-loop adaptation works well (slow, over the task distribution). The inner loop learns a task; the outer loop learns how to learn.
    2. MED Why does MAML require second-order gradients, and what does the first-order approximation drop?
      Solution
      The outer objective is $L^{\text{query}}(\theta - \alpha\nabla L^{\text{support}}(\theta))$; differentiating wrt $\theta$ by the chain rule passes through the inner gradient $\nabla L^{\text{support}}(\theta)$, whose derivative is the Hessian — hence second order. The outer gradient is $(\mathbf I - \alpha \nabla^2 L^{\text{support}}) \nabla L^{\text{query}}(\theta')$. First-order MAML (FOMAML) drops the Hessian term (treats $\theta'$ as if not a function of $\theta$), using just $\nabla L^{\text{query}}(\theta')$ — cheaper, and empirically close because near a good initialization the Hessian term is small; it discards the "how the adaptation itself changes with $\theta$" signal.
    3. HARD Meta-learning can also fail to generalize — to task shift. Explain meta-overfitting and how it mirrors ordinary overfitting one level up.
      Solution
      Ordinary overfitting: fit the training examples so well that held-out examples suffer. Meta-overfitting: fit the training task distribution so well that held-out tasks (from a shifted task distribution) suffer — the meta-learner exploits regularities specific to the training tasks (e.g. memorizes that support sets always have a certain structure, or that all tasks share a hidden constant) rather than learning a general adaptation procedure. It mirrors the level-below exactly: the "training set" is now tasks, the "capacity" is the meta-learner's ability to specialize its adaptation to seen tasks, and the "regularization" is task diversity (more, more varied meta-training tasks) and constraints on the adaptation procedure. No-free-lunch reappears (Ch 20): a meta-learner is only general over the task distribution it meta-trained on; claiming task-general adaptation requires the meta-training tasks to be representative of deployment tasks — the same representativeness assumption as one level down, which is why measuring generality (below) must specify the reference task distribution at the meta level too.

    Few-shot learning

    Few-shot learning is doing a task from a handful of examples — the human-obvious ability that classical ML lacked. Show a child two giraffes and they recognize the third; classical classifiers needed thousands. Few-shot competence is a hallmark of the flexible generalization we associate with intelligence, and modern foundation models exhibit it strikingly through in-context learning.

    Definition A $k$-shot, $N$-way task provides $k$ labeled examples for each of $N$ classes (the support set) and asks for classification of new queries. Few-shot performance is accuracy as a function of $k$ (small). It is achieved by leveraging prior knowledge: a strong representation (from pretraining/meta-learning) in which classes separate with few examples, so the $k$ examples locate a decision boundary rather than learn features from scratch.
    Worked example Prototypical networks, 5-way 1-shot. Embed all images with a pretrained encoder $g$. Each class prototype = mean of its support embeddings (with 1-shot, just that one embedding). Classify a query $x$ by nearest prototype in embedding space: $\hat y = \arg\min_c \lVert g(x) - c_c \rVert$. All the work is in $g$: if pretraining shaped $g$ so same-class images cluster, one example per class pins the cluster centers and 1-shot classification works. Concretely with 2-D embeddings: prototypes at $(0,0)$ and $(3,1)$ from one example each; query at $(2.5, 1.2)$ → distances $\sqrt{2.5^2+1.2^2} = 2.77$ vs $\sqrt{0.5^2 + 0.2^2} = 0.54$ → class 2. The representation did the heavy lifting; the "learning" was computing a mean.
    Where this goes Zero-shot (next) is the $k=0$ limit; in-context learning (Ch 23) is few-shot without weight updates; and few-shot ability is a key axis of the capability and generality measurements later in this chapter.
    Drill
    1. EASY Why is few-shot learning impossible without strong prior knowledge?
      Solution
      $k$ examples per class carry too little information to determine both a good representation and a decision boundary from scratch — the problem is massively underdetermined (Ch 20: sample complexity far exceeds $k$). Prior knowledge (a pretrained representation, an inductive bias) supplies the missing constraints, so the few examples only need to locate the answer within an already-structured space.
    2. MED In prototypical networks, 5-way 5-shot beats 5-way 1-shot. Why, statistically?
      Solution
      The prototype is the mean of $k$ support embeddings; with $k=5$ the mean has variance $\sigma^2/5$ versus $\sigma^2$ at $k=1$ (Ch 11) — a more accurate class center, so fewer misclassifications from a noisy prototype. Diminishing returns set in as $k$ grows (variance $\propto 1/k$), which is why the jump from 1 to 5 shots is large and from 50 to 55 negligible.
    3. HARD Few-shot accuracy of foundation models improves with model scale even at fixed $k$. Explain via the representation and the meta-learning view, and predict when adding shots stops helping.
      Solution
      Scale improves the pretrained representation: larger models learn features on which more tasks' classes separate cleanly and linearly (better manifold coverage, transfer topic), so the same $k$ examples locate a better-conditioned boundary — few-shot accuracy rises with scale at fixed $k$. Meta-learning view: scale + data diversity strengthens the implicit in-context learning algorithm (the model has "seen" more task structures during pretraining), so it adapts more sample-efficiently. When does adding shots stop helping? When the bottleneck shifts from locating the boundary (helped by more shots) to the representation's ceiling (whether the classes are separable in the embedding at all) or the model's context/algorithmic limits. Concretely: on tasks well-covered by pretraining, few shots saturate quickly (the prior is strong, extra examples add little); on tasks far from pretraining, more shots help longer but plateau below full performance because no number of in-context examples can install features the weights lack — the shots can only reweight existing features. This predicts the observed pattern: strong models are near-flat in $k$ on familiar tasks and steeply $k$-dependent on novel ones, and the plateau height measures the representation's coverage of the task — again turning an ability into a measurement.

    Zero-shot learning

    Zero-shot learning is performing a task with no examples — only a description. Recognize a "zebra" having never seen one, told only "a horse with black-and-white stripes." It demands that knowledge be composed across modalities or from language alone, and it is the clearest test of whether a system has genuinely general, transferable concepts rather than task-specific pattern matches.

    Definition Zero-shot classification maps inputs to classes never seen in training, using auxiliary information (class descriptions, attributes, or a shared embedding space) instead of labeled examples. The standard mechanism: embed inputs and class descriptions into a shared space (e.g. CLIP's joint image–text space) and classify by similarity: $\hat y = \arg\max_c \, g_{\text{input}}(x)^\top g_{\text{desc}}(\text{description}_c)$. The transfer is from the description-to-embedding map learned on other classes.
    Worked example CLIP-style zero-shot. Encode an image to a vector; encode candidate label prompts "a photo of a {cat/dog/zebra}" to vectors in the same space; predict the label whose text embedding has highest cosine similarity to the image embedding. The zebra class was never a training label, but "zebra," "stripes," "horse" all appeared in the text-image pretraining, so the text encoder places "a photo of a zebra" near striped-equine images. Numeric sketch: image embedding $u$; similarities $\cos(u, v_{\text{cat}}) = 0.12$, $\cos(u, v_{\text{zebra}}) = 0.31$, $\cos(u, v_{\text{dog}}) = 0.09$ → predict zebra. The compositional language understanding (Ch 21) plus the shared space does what examples would otherwise.
    Pitfall Zero-shot claims are only meaningful if the classes are genuinely absent from training — and with web-scale pretraining, "unseen" is nearly impossible to guarantee (the zebra, and descriptions of it, are in the data). Much apparent zero-shot generalization is really "seen in pretraining, unseen as a labeled task" — a real and useful capability, but not the strong claim of concepts assembled from never-before-encountered parts. Contamination (below) is the same problem for benchmarks.
    Drill
    1. EASY What replaces labeled examples in zero-shot learning?
      Solution
      Auxiliary descriptions in a shared representation space — class names, attribute lists, or natural-language definitions — plus a learned map (from other classes) that places inputs and descriptions near each other when they match.
    2. MED Why does a shared image–text embedding space enable zero-shot transfer that separate encoders cannot?
      Solution
      In a shared space, an image and its matching description land near each other by construction of the training objective (contrastive alignment, Ch 21's InfoNCE). So a novel class only needs a description — its text embedding is automatically comparable to any image embedding, no examples required. Separate, unaligned encoders produce embeddings in incomparable spaces; there is no meaningful similarity to compute between an image vector and a text vector, so the description can't be used to score images. Alignment is what makes language a usable interface to visual classification.
    3. HARD Distinguish three senses of "zero-shot" of increasing strength, and say which current systems actually demonstrate.
      Solution
      (1) Weak: class unseen as a labeled task but present in pretraining data (the CLIP zebra) — demonstrated ubiquitously; it's really transfer from pretraining, valuable but not concept-assembly. (2) Medium: novel composition of seen attributes — "a purple three-legged dog," where dog, purple, three-legged were each seen but not combined; requires compositional binding (compositionality topic). Current systems do this partially and unreliably, better with scale. (3) Strong: a genuinely novel concept defined only by description at inference, with parts also novel or novelly related — requires reasoning from the definition to build a classifier on the fly. Largely aspirational; where it appears it's usually reducible to (1) or (2) on inspection. The strength ladder matters for AGI claims: only (3) is "understanding a new concept from its description," and rigorously demonstrating it requires provable absence of the concept and its close relatives from training — which web-scale data makes extraordinarily hard, tying back to the contamination problem and making clean zero-shot evaluation a genuine methodological frontier.

    Skill composition

    Compositionality applied to abilities: an intelligent agent that has learned to open doors and to carry objects should be able to carry an object through a door without separate training. Skill composition is the reuse and combination of learned sub-skills to solve tasks that no single skill covers — the behavioral engine of open-ended competence and a central goal of hierarchical RL and modern agents.

    Definition Given a library of skills (policies/options) $\{\pi_1, \dots, \pi_m\}$, skill composition solves a new task by sequencing (do $\pi_i$ then $\pi_j$), selecting (a higher-level policy choosing which skill when — options framework / hierarchical RL, Ch 25), or blending skills, without relearning the primitives. An option is a triple (initiation set, sub-policy, termination condition); a meta-policy composes options into behavior over extended horizons.
    Worked example Hierarchical navigation. Primitives (options): "go to kitchen," "pick up cup," "go to table," "put down." A new task "bring the cup to the table" needs no new low-level learning — a meta-policy sequences: go-to-kitchen → pick-up-cup → go-to-table → put-down. The meta-policy's action space is 4 options, not thousands of motor commands, so it learns/plans over a horizon of 4 decisions instead of thousands — the temporal abstraction that makes long tasks tractable (Ch 25's semi-MDP). Failure mode to notice: composition breaks if an option's termination leaves the world outside the next option's initiation set (arrive at kitchen but cup is on a high shelf — "pick up cup" can't initiate); robust composition requires the primitives' pre/postconditions to chain (exactly Ch 34's contract composition, now for skills).
    Think first Why is composing skills harder than composing functions, even when each skill works perfectly alone?
    Reveal
    Because skills act in a shared, stateful world with side effects and preconditions. Function composition $f \circ g$ just needs type-matching; skill composition needs $\pi_i$'s termination state to satisfy $\pi_j$'s initiation conditions (the world must be left in a state the next skill can start from), and $\pi_i$ may have altered the environment in ways that break assumptions $\pi_j$ was trained under. It's composition over a mutable world-state, so the same pre/postcondition-chaining discipline as program verification (Ch 34) applies — and its absence is why naively sequenced skills fail even when each is individually reliable.
    Drill
    1. EASY What are the three parts of an "option" in hierarchical RL, and what does each control?
      Solution
      Initiation set (where the option can start), sub-policy (how it acts while running), termination condition (when it hands control back). Together they package a temporally extended behavior as a single choosable action for the meta-policy.
    2. MED A meta-policy chooses among 6 options to solve tasks of horizon 60 primitive steps, with options averaging 10 steps each. Contrast the effective planning horizon and branching with flat RL.
      Solution
      Flat: horizon 60, branching = size of primitive action space (say $A$) → search/credit-assignment over $A^{60}$. Hierarchical: horizon $60/10 = 6$ option-decisions, branching 6 → $6^6 \approx 4.7\times10^4$, astronomically smaller, and credit is assigned over 6 decisions not 60. Temporal abstraction shortens the effective horizon (easier credit assignment, Ch 25) and shrinks the decision branching — the two reasons hierarchy helps long-horizon tasks, provided the option library is good.
    3. HARD Skill composition can suffer compounding preconditions failures over long sequences. Model the reliability and state what it implies for how skills should be designed.
      Solution
      If each of $n$ sequenced skills succeeds (leaves the world in the next's initiation set) with probability $p$, the sequence succeeds with $p^n$ — e.g. $p=0.95$, $n=10$ → $0.60$; $n=20$ → $0.36$. Exponential decay means long compositions are fragile even with reliable primitives. Implications for skill design: (1) build skills with wide initiation sets and robust termination (they should succeed from many start states and leave the world in a canonical, well-defined state — like idempotent, precondition-tolerant operations in Ch 32/34), raising per-step $p$ toward 1; (2) include recovery/verification between skills (a "checker" option that detects and repairs off-nominal states — the executor–verifier pattern of Ch 33), converting silent failures into caught-and-retried ones so effective reliability compounds much slower; (3) prefer hierarchies that keep composition depth shallow (reusable mid-level skills over deep towers of primitives). This is the same lesson as multi-step agent reliability (Ch 33's plan decomposition) and program composition (Ch 34's contract chaining): long autonomous behavior requires either near-perfect primitives or explicit inter-step verification — which is precisely what autonomy measurement (below) must probe.

    Representation learning

    How data is represented determines what is easy to compute from it. Representation learning is the automatic discovery of features that make downstream tasks easy — replacing hand-engineered features with learned ones. It is arguably the core reason deep learning works: the same raw pixels are hopeless for a linear classifier and trivial for one operating on learned high-level features.

    Definition A representation is a map $g: \mathcal X \to \mathbb R^d$ from raw inputs to a feature space. Representation learning optimizes $g$ (often via self-supervision, contrastive, or reconstruction objectives) so that useful tasks become simple functions of $g(x)$ — ideally linear. Quality is measured by downstream ease: linear-probe accuracy, sample efficiency of transfer, and the geometry of the space (do semantically related inputs cluster, do meaningful directions exist).
    Worked example Linear separability as the yardstick. Raw 784-pixel MNIST: a linear classifier reaches ~92% (digits aren't linearly separable in pixel space). A representation learned by a self-supervised encoder maps the same digits to a space where a linear probe hits ~99% — the encoder folded the manifold (Ch 9) so classes became linearly separable. The measurable claim: representation quality = how linear the downstream task became. This is why linear probing (Ch 35) is the standard representation-quality metric — it asks "did the hard nonlinear work already get done by $g$?"
    Where this goes Disentangled representations (next) are a specific structural goal for $g$; world models (below) are representations optimized for prediction and control; and the quality of an agent's representations upper-bounds its transfer, few-shot, and compositional abilities (all above).
    Drill
    1. EASY Why is linear-probe accuracy a natural measure of representation quality?
      Solution
      If a linear classifier on top of $g(x)$ solves the task, then $g$ has already done all the nonlinear work of extracting the relevant structure — the representation "exposes" the task. High linear-probe accuracy means the useful information is present and easily accessible, which is exactly what a good representation should provide for downstream reuse.
    2. MED Contrast the inductive biases of contrastive vs reconstruction (autoencoding) representation objectives.
      Solution
      Contrastive (InfoNCE, Ch 21): pulls augmentations of the same input together and different inputs apart — learns features invariant to the chosen augmentations and discriminative across instances; tends to discard information irrelevant to distinguishing instances (can lose fine detail). Reconstruction: forces the representation to retain enough to rebuild the input — keeps more information including task-irrelevant detail, so features may be less directly discriminative but more complete. The bias is set by the objective: contrastive asks "what distinguishes," reconstruction asks "what suffices to regenerate" — choose per downstream need.
    3. HARD State the tension between compression and sufficiency in representation learning, connecting to the information bottleneck (Ch 16).
      Solution
      The information bottleneck frames representation learning as: find $g(X)$ minimizing $I(X; g(X))$ (compression — throw away input information) subject to maximizing $I(g(X); Y)$ (sufficiency — keep what predicts the target), i.e. $\min I(X; g(X)) - \beta I(g(X); Y)$. Tension: maximal sufficiency wants to keep everything predictive; maximal compression wants to keep only that, discarding nuisance variation. The ideal representation is a minimal sufficient statistic (Ch 13) for $Y$ — exactly enough to predict, nothing more, giving invariance to nuisances for free. For AGI the catch is that "$Y$" is unknown/open-ended: a representation compressed toward one task's sufficiency (small $I(X;g)$ tuned for $Y_1$) may discard information a future task $Y_2$ needs. Hence general-purpose representations deliberately under-compress (keep broadly-useful information, high $I(X;g)$) — the self-supervised bet that predicting everything (the data itself) yields features sufficient for many unknown future $Y$'s. Generality trades optimal per-task compression for broad sufficiency, which is why foundation-model representations are large and redundant rather than minimal.

    Disentangled representations

    A disentangled representation is one where separate factors of variation in the world map to separate, independent directions in the code — one axis for object position, another for color, another for lighting, each movable without disturbing the others. The appeal: such representations are interpretable, compositional, and transfer cleanly, mirroring the world's own modular structure.

    Definition Given data generated by independent factors $z = (z_1, \dots, z_k)$ (position, size, color…), a representation $g(x) = \hat z$ is disentangled if each learned coordinate recovers one true factor (up to permutation/scaling) and is invariant to the others: changing $z_i$ moves only $\hat z_i$. Measured by metrics like modularity/compactness (each latent responds to one factor) and explicitness (factors linearly decodable).
    Worked example A dataset of shapes varying in (x-position, y-position, scale, rotation, color). A perfectly disentangled 5-D code has one coordinate tracking each: traverse latent 3 alone and only scale changes, everything else fixed. Test image manipulation: set $\hat z = (0.2, 0.8, 0.5, 0.0, \text{red})$, then increment coordinate 4 → the same shape at the same place, only rotated. An entangled code (e.g. raw PCA) mixes factors: moving one principal component changes position and scale together, so you cannot independently control them. The measurable difference is whether single-latent traversals produce single-factor changes.
    Pitfall Unsupervised disentanglement is not identifiable in general (Locatello et al.): without inductive biases or supervision, infinitely many equally-good generative models entangle the factors differently, so no purely unsupervised objective can guarantee recovering the "true" factors — reported successes often depend on lucky random seeds and factor-aware metrics. Disentanglement needs some supervision, known structure, or interventional data (Ch 27) to be well-posed.
    Drill
    1. EASY What is the practical payoff of a disentangled representation?
      Solution
      Independent, interpretable control and clean transfer: you can manipulate one factor without side effects (useful for editing, controllable generation), read off factors directly (interpretability), and reuse factor-axes across tasks that share factors. It mirrors the world's modularity, so downstream learning about one factor doesn't require relearning others.
    2. MED Why does the independence of factors matter, and how can it fail even in a "disentangled" model?
      Solution
      Independence lets each latent be varied freely to generate valid data (compositional coverage) and ensures changing one factor doesn't force changes in another. It fails when true factors are correlated in the data (e.g. large objects are usually near, so scale and position co-vary): a model trained on such data may bind the correlated factors into one latent or refuse to generate their unlikely combinations, so "disentanglement" measured on the training correlation structure breaks under intervention (setting the factors independently produces artifacts). Genuine disentanglement is about the causal factors (Ch 27), which correlational data underdetermines.
    3. HARD Given the impossibility result, what makes disentanglement achievable, and why is this the same lesson as causal identification (Ch 27) and goal underdetermination (Ch 35)?
      Solution
      Achievable via added constraints that break the symmetry among equally-good entangled solutions: (1) weak supervision (a few labeled factors, or knowing which pairs share/differ in a factor); (2) interventional/grouped data — observations where one factor is held fixed or explicitly changed (exactly Ch 27's interventions, which identify causal factors that observational data cannot); (3) architectural/temporal biases (factors that vary at different timescales, or sparsity of factor-changes between frames — a factor rarely changes alone in video, used by object-centric models); (4) known mechanisms. The unifying lesson across three chapters: observational data underdetermines structure — disentanglement (which latent is which factor), causal graphs (Ch 27, which variable causes which), and learned goals (Ch 35, which objective the policy pursues) are all non-identifiable from passive data alone because multiple structures fit identically. In every case the cure is the same: additional assumptions or interventions that distinguish the candidates. It is one epistemological fact wearing three hats — you cannot recover structure the data was blind to without injecting an inductive bias or an intervention, and honest generality measurement (below) must account for which biases were injected.

    World models

    A world model is an agent's internal predictive simulator: given a state and an action, it predicts what happens next. With one, an agent can plan by imagining consequences rather than acting them out, learn from imagined rollouts, and reason counterfactually. Chapter 29 built these in depth; here we place them as a pillar of general intelligence — the substrate that turns reaction into foresight.

    Definition A world model is a learned dynamics function, typically in a latent space: an encoder $z_t = e(o_{\le t})$, a transition model $\hat z_{t+1} = f(z_t, a_t)$, and often reward/observation decoders. It supports imagination: rolling out $f$ from a state to predict trajectories without environment interaction, enabling model-based planning and policy learning in imagination (Ch 25, 29).
    Worked example A Dreamer-style agent (Ch 29): learn a latent dynamics model from experience, then train the policy entirely inside the model's imagined rollouts — thousands of imagined trajectories per real environment step. The payoff is sample efficiency: real interactions are expensive, imagined ones are free, so the agent extracts far more learning per real step. The load-bearing quantity is model accuracy over the rollout horizon — errors compound (Ch 29's compounding error), so imagined training helps only as far as the model stays faithful, typically a limited horizon before predictions drift.
    Where this goes World models unify planning (imagine and optimize actions), reasoning (counterfactual rollouts), and the manifold/representation ideas above (the latent space is a learned representation optimized for prediction). Their fidelity horizon bounds the planning depth (next) an agent can trust.
    Drill
    1. EASY Why does having a world model improve sample efficiency?
      Solution
      The agent can learn from imagined rollouts generated by the model instead of only from expensive real environment interactions — many "practice" trajectories per real step. It reuses each real experience to improve the model, then mines the model for far more learning signal than the raw experience provided.
    2. MED A world model has per-step prediction error that grows the rollout error as $\epsilon_h \approx \epsilon_1 \cdot \frac{L^h - 1}{L - 1}$ for Lipschitz constant $L > 1$. What does this imply for planning horizon, and how do agents cope?
      Solution
      Rollout error grows (roughly geometrically for $L>1$) with horizon $h$, so beyond some $h^*$ the imagined trajectory is too inaccurate to plan on — the trustworthy planning horizon is bounded by model fidelity. Agents cope by: short imagined horizons with a learned value function bootstrapping the tail (Ch 25's value estimate absorbs long-term consequences the model can't predict), replanning frequently (model-predictive control, Ch 28 — re-image from the true state each step so errors don't accumulate across the whole task), and uncertainty-aware models that shorten rollouts when confidence drops. Fidelity, not compute, sets the horizon.
    3. HARD Contrast latent-space world models (JEPA/Dreamer-style, predict in representation space) with pixel-space video prediction for building general agents, using the representation-learning ideas above.
      Solution
      Pixel/observation-space prediction models the full observation, spending capacity on reconstructing every detail — including unpredictable, task-irrelevant nuisance (leaves fluttering, sensor noise, exact textures). This is wasteful and can be actively harmful: the model is penalized for failing to predict inherently-unpredictable pixels, distracting it from the controllable, decision-relevant dynamics. Latent-space models (JEPA, Ch 29) predict in a learned representation space, so they only need to predict the abstract features that matter, discarding nuisance by construction — the information-bottleneck logic (representation topic): keep what's sufficient for prediction/control, compress away the rest. Consequences for general agents: latent models scale to complex, noisy environments where pixel prediction drowns in detail; they align the world model with the representation (the same features serve perception, prediction, and control); and they sidestep the "curse of prediction" where a perfect pixel predictor wastes all capacity on irreducible noise. The tradeoff: latent prediction can collapse (predict a constant, trivially "accurate" in a degenerate latent space) without care — requiring the anti-collapse mechanisms of self-supervised learning. The design principle for AGI world models: predict in a space chosen so that predictability correlates with decision-relevance, which is exactly what representation learning optimized for control provides.

    Planning

    Planning is choosing actions by looking ahead — reasoning over possible futures to select what to do now. Chapters 25–26 developed the algorithms; here planning stands as a core faculty of general intelligence, the ability to bridge from present state to distant goals through a chosen sequence of actions, and the faculty that most distinguishes deliberate agents from reactive ones.

    Definition Planning: given a model of dynamics (a world model or known transition function), a goal or reward, and a current state, compute a policy or action sequence optimizing expected return over a horizon. Approaches span search (A*, MCTS — Ch 26), dynamic programming (value/policy iteration — Ch 25), and trajectory optimization (Ch 28). Planning depth (horizon), branching, and model fidelity set its cost and its reach.
    Worked example Model predictive control loop (Ch 28) as general-purpose planning: at each step, use the world model to simulate candidate action sequences over a short horizon $H$, pick the sequence with best predicted return, execute only the first action, then re-plan from the new true state. This exploits the model where it's accurate (near term) and corrects drift by re-observing — trading exhaustive long-horizon planning for repeated cheap short-horizon planning. It is the same insight as reasoning's test-time compute (below): spend computation at decision time to look ahead, rather than baking all decisions into a reactive policy.
    Think first Why does an LLM doing chain-of-thought resemble planning, and where does the analogy break?
    Reveal
    Resembles: chain-of-thought spends test-time computation exploring intermediate steps before committing to an answer — like planning's look-ahead, and tree-of-thought (Ch 30) makes the search explicit. Breaks: classical planning has an explicit, queryable world model and evaluates states against a defined objective; CoT's "look-ahead" is implicit in the model's learned distribution, with no guaranteed-accurate transition model or explicit value function — it can hallucinate consequences. The gap is exactly a reliable world model: planning is only as good as its model, and LLMs' implicit world models are strong on familiar dynamics, unreliable on novel ones (Ch 29). This motivates tool-verified and formal-model-augmented reasoning (Ch 30, 34).
    Drill
    1. EASY Why does model predictive control execute only the first planned action then re-plan?
      Solution
      To correct model error and disturbances: re-observing the true state after each action prevents rollout errors from compounding across the whole task (the world model is trusted only over the short horizon where it's accurate). It trades extra planning computation for robustness to an imperfect model — closed-loop beats open-loop when the model or world is uncertain.
    2. MED A planner searches depth $d$ with branching $b$; a good heuristic/value function lets it prune. Explain the cost with and without, and the role of the value function.
      Solution
      Uninformed full search: $O(b^d)$ nodes — exponential in depth. A value function estimates the return from a state, so the planner can (a) truncate rollouts early and use the value as the tail estimate (reducing effective $d$), and (b) focus search on promising branches (best-first/MCTS with value-guided selection, Ch 26), pruning low-value subtrees. Effect: search cost drops toward the branching along the good path rather than the whole tree. The value function amortizes deep search into a learned estimate — the AlphaZero insight (Ch 26): learned value + policy priors turn intractable game-tree search into feasible guided search.
    3. HARD Planning, learning, and reasoning are often posed as alternatives; argue they are facets of one thing, using the value function and world model as the connective tissue.
      Solution
      They share a common structure: choosing actions to optimize expected outcomes given a model. (1) Planning = search using a world model at decision time (explicit look-ahead). (2) Model-free learning = amortizing the results of (implicit) planning into a reactive policy/value function via experience — the value function caches the outcome of look-ahead so you don't re-plan (Ch 25). (3) Reasoning (below) = planning over an abstract state space of propositions/thoughts rather than physical states, with the "world model" being logical/causal transitions. The connective tissue: a world model (what happens if) plus a value function (how good is a state) supports all three — planning uses them online, learning distills them offline, reasoning applies them over abstract states. AlphaZero literally unifies planning and learning (search generates targets that train the value/policy, which in turn guide search — a self-improving loop); test-time-compute reasoning (below) is the same loop in language. For AGI the implication is that these aren't competing paradigms to choose among but complementary uses of the same two learned functions, and a general agent needs both a good model and a good value estimate, deployed with a flexible online/offline compute tradeoff — spending test-time computation (planning/reasoning) exactly where the cached policy is unreliable.

    Reasoning

    Reasoning is drawing conclusions that go beyond the immediately given — deduction, induction, abduction, and search over intermediate steps. Chapter 30 developed it fully; here it stands as a pillar of general intelligence, the faculty that composes knowledge into new knowledge and lets a system solve problems it has no memorized answer for by working them out.

    Definition Reasoning is the production of new justified beliefs or plans from existing ones via valid (or plausible) inference steps. In modern systems it appears as multi-step computation at inference time — chain-of-thought, tree/graph search over thoughts (Ch 30), tool-augmented and verified steps — trading test-time compute for accuracy on problems requiring composed inference. Process supervision (Ch 30) rewards the steps; outcome supervision rewards only the answer.
    Worked example A hard arithmetic/logic problem answered directly is often wrong; the same model producing step-by-step reasoning (decompose → solve subparts → combine) succeeds — because each step is an in-distribution, low-difficulty operation, and the chain composes them (compositionality topic). Test-time-compute scaling: sampling more reasoning paths and selecting (self-consistency, Ch 30) or searching over them (tree-of-thought) trades inference compute for accuracy — a distinct scaling axis from model size. The measurable regularity: accuracy rises with reasoning-token budget on problems that decompose, and doesn't on problems that don't (pure recall) — again, the task structure determines whether the faculty helps.
    Where this goes Reasoning + planning + world models + memory are the four cognitive faculties this chapter names as jointly necessary for general intelligence; their integration, not any one alone, is the open architectural question the AGI-evaluation topics try to measure.
    Drill
    1. EASY Why does chain-of-thought help on multi-step problems but not on pure-recall questions?
      Solution
      Multi-step problems decompose into simple operations the model can each do reliably; writing them out lets the model compose reliable steps instead of attempting an unreliable one-shot leap. Pure recall has no steps to decompose — the answer is either known or not — so extra reasoning tokens add nothing (and can add errors).
    2. MED Distinguish process supervision from outcome supervision and give a case where outcome supervision is dangerous.
      Solution
      Outcome supervision rewards only the final answer's correctness; process supervision rewards each reasoning step. Outcome supervision is dangerous when a wrong process yields a right answer (rewarding flawed reasoning that happened to work — it learns lucky shortcuts) or when it incentivizes unfaithful reasoning: the model may produce a plausible-looking chain unrelated to its actual (opaque) computation, since only the answer is graded (Ch 35's CoT-faithfulness concern). Process supervision rewards sound intermediate steps, encouraging faithful, verifiable reasoning — at the cost of needing step-level labels (a process reward model, Ch 30).
    3. HARD Test-time compute (more reasoning) and train-time compute (bigger model) are substitutable to a degree. Discuss the tradeoff and its implications for what "intelligence" is being measured.
      Solution
      Empirically, a smaller model given more inference-time reasoning (search, sampling, verification) can match a larger model answering directly, on problems amenable to search/verification — the two compute axes trade off. Analysis: train-time compute installs amortized capability (fast, cached "System-1" competence); test-time compute performs deliberate search at decision time ("System-2"), effective when the problem admits decomposition or when a verifier can select among attempts (the generator–verifier gap, Ch 33). The tradeoff has a frontier: test-time compute helps most where verification is cheaper than generation and where the base model's step-competence is adequate to compose; it cannot conjure capabilities the base model's steps lack. Implications for measuring intelligence: capability is not a single scalar of the weights — it depends on the inference-time compute budget and scaffolding, so any evaluation must specify the compute/scaffolding regime (a model is "able to solve X" only relative to an allowed reasoning budget). This reframes capability measurement (below) as measuring a capability-vs-compute curve, not a point, and it blurs the model/agent distinction — the same weights are more capable with more thinking, which is precisely why autonomy and capability evaluations (below and Ch 35) must fix and report the elicitation/compute conditions, or the numbers are meaningless.

    Memory

    Intelligence needs to persist and retrieve information across time — a working scratchpad for the current problem, and long-term stores of facts, experiences, and skills. Chapter 31 detailed agent memory systems; here memory stands as a pillar of general intelligence, the faculty that lets an agent accumulate and reuse knowledge rather than restarting from zero each moment.

    Definition Memory in an intelligent system spans: parametric memory (knowledge in weights, written by training), working memory (the active context — an LLM's context window, Ch 21), and external/episodic memory (retrievable stores: vector databases, logs — Ch 31). The faculties are write (consolidate), store (retain), and retrieve (recall relevant items on demand), each with capacity, persistence, and access-cost tradeoffs.
    Worked example Three memory types, three roles, one task: an agent debugging a codebase over days. Parametric memory holds general programming knowledge (from pretraining — vast, fixed, no per-task write). Working memory (context window) holds the current file and recent reasoning (fast, limited to ~context length, erased between sessions). Episodic/external memory holds project-specific facts learned earlier ("the auth module uses library X, decided last Tuesday"), stored in a retrievable database and pulled into context when relevant (Ch 31's retrieval). The capability gap without external memory: the agent re-derives or forgets project context each session — the difference between an employee and a temp who resets nightly.
    Where this goes Memory + continual learning (above) together enable an agent to accumulate skills over a lifetime; the write path connects to catastrophic forgetting (parametric) and to memory provenance/contradiction (external, Ch 31); and reliable long-term memory is a prerequisite for the autonomy measured below.
    Drill
    1. EASY Match each to its role: parametric, working, episodic memory.
      Solution
      Parametric = general knowledge in weights (broad, slow to write via training, always available). Working = active context for the current task (fast, small, transient). Episodic/external = specific past experiences/facts in a retrievable store (large, persistent, accessed on demand via retrieval).
    2. MED Why can't you just use a huge context window instead of external memory? Give two reasons.
      Solution
      (1) Cost/scaling: attention over a context of length $n$ costs $O(n^2)$ (or $O(n)$ with a KV cache per token, Ch 23) — an unboundedly growing lifetime of experience is infeasible to keep in context, and retrieval fetches only the relevant slice. (2) Persistence and selectivity: context is erased between sessions and holds everything undifferentiated, while external memory persists across sessions, supports selective retrieval of the relevant items (avoiding distraction/dilution, Ch 31's context management), and can be edited, versioned, and provenance-tracked. Even with long context, you still want a curated, persistent store — context is working memory, not long-term memory.
    3. HARD Design the memory architecture for an agent that must learn continually without catastrophic forgetting, combining this chapter's ideas. Identify what each component protects against.
      Solution
      Layered memory: (1) Frozen/slow parametric core — broad pretrained knowledge, updated rarely and carefully (or via parameter-efficient adapters, which localize changes and resist forgetting, catastrophic-forgetting topic) — protects general competence from being overwritten by recent experience. (2) External episodic store (vector DB, Ch 31) for specific experiences/facts — written cheaply per experience, retrieved on demand — provides continual accumulation without touching weights, sidestepping catastrophic forgetting entirely for factual knowledge (you add rows, you don't move weights). (3) Working memory (context) assembled per task from retrieved episodic items + current input — provides task-specific integration. (4) Consolidation process (memory topic + Ch 31): periodically distill frequently-useful episodic knowledge into the parametric core via replay-based training (replaying stored experiences prevents forgetting during this write, continual-learning topic) — the "sleep" that moves reliable knowledge from fast external store to slow weights. What each protects: adapters/replay protect old parametric skills during updates; external store makes most learning non-destructive (no weight change); provenance/contradiction handling (Ch 31) protects against corrupt or stale memories; consolidation prevents the external store from growing unboundedly while promoting durable knowledge. The architecture mirrors human complementary learning systems (fast hippocampal episodic + slow neocortical consolidation) — and its correctness rests on keeping most continual learning in the addable external store, using weight updates (the forgetting-prone channel) sparingly and with replay. This is the concrete synthesis of memory + continual learning + forgetting that a lifelong general agent requires.

    Autonomy

    Autonomy is the capacity to pursue goals over extended periods with little human intervention — deciding what to do next, recovering from errors, and staying on task across long horizons. It is the axis along which "a model that answers questions" becomes "an agent that gets things done," and the axis most consequential for both usefulness and risk.

    Definition Autonomy is the degree to which a system operates without human input: measured by task horizon (how long a task it can complete unsupervised), intervention rate (human corrections per unit work), and scope of decisions delegated. It requires the integration of planning, memory, error recovery, and self-monitoring — an agent loop (Ch 31) that sustains coherent goal-pursuit across many steps without drift or derailment.
    Worked example The task-horizon metric (a concrete autonomy measure): find the length of task — measured in how long a human expert takes — that a model completes with, say, 50% success unsupervised. A model reliable on 5-minute tasks but failing 2-hour tasks has a short autonomy horizon; the empirical trend (e.g. METR-style measurements) is that this horizon has been growing over model generations. Why horizon is the right axis: failure probability compounds over steps (skill-composition topic: $p^n$), so longer tasks are exponentially harder to complete without intervention — the horizon at fixed success rate captures the compounding-reliability frontier in one number, and its growth over time is a leading indicator of increasing autonomy.
    Pitfall Autonomy is not a pure capability — it's capability × reliability × error-recovery, and the reliability term dominates at long horizons. A model that is brilliant but occasionally derails has low autonomy despite high peak capability, because one uncaught error ends a long task. Conversely, modest capability with strong self-correction (verify-and-retry, Ch 33) yields high autonomy. Measuring "how smart" misses this; autonomy measurement (below) must probe sustained, self-correcting goal-pursuit, not one-shot skill.
    Drill
    1. EASY Name three ingredients autonomy requires beyond raw task skill.
      Solution
      Error recovery (detect and fix mistakes without human help), memory (maintain goal and context over long horizons), and self-monitoring/planning (decide next steps, know when to stop or escalate). Raw skill on a single step is necessary but far from sufficient for sustained unsupervised operation.
    2. MED If per-step success is $p = 0.99$ and a task needs $n$ steps with no error recovery, at what $n$ does unsupervised success fall below 50%? How does error recovery change this?
      Solution
      Success $= 0.99^n < 0.5 \Rightarrow n > \ln 0.5 / \ln 0.99 \approx 69$ steps — so even 99% per-step reliability caps autonomous tasks at ~70 steps before coin-flip failure. Error recovery (a verify-and-retry loop, Ch 33) raises effective per-step success toward $1 - (\text{miss rate of the checker}) \times (\text{failure rate})$: if a checker catches 90% of the 1% step-failures, effective failure drops to ~0.1%, pushing the 50% horizon to ~690 steps — a 10× horizon extension from recovery alone. This is why autonomy is dominated by reliability and self-correction, not peak skill, and why long-horizon agents invest heavily in verification.
    3. HARD Autonomy is jointly a usefulness axis and a risk axis. Explain the double-edged nature and how it interacts with the control and scaling ideas of Ch 35.
      Solution
      Same property, both signs: autonomy is what makes agents economically valuable (complete long tasks unsupervised) and what makes them risky (act at length without human oversight, so errors or misalignment can compound and propagate before a human intervenes — Ch 35). The interaction: (1) Longer autonomy horizons mean fewer human checkpoints per unit of consequence, shrinking the oversight bandwidth exactly as the stakes per uninterrupted run grow — scalable oversight (Ch 35) must scale with autonomy or the gap widens. (2) Control (Ch 35) becomes both more necessary and harder: monitoring an autonomous agent requires trusted checkers that can keep up over long horizons, and the agent's error-recovery (good for usefulness) can also route around safety interventions (bad). (3) Autonomy measurement is therefore a dangerous-capability-adjacent evaluation (Ch 35): the autonomy horizon is precisely a threshold a responsible-scaling policy should gate on, because autonomy to complete long beneficial tasks is inseparable from autonomy to complete long harmful ones. The design response is to couple autonomy with proportionate control — irreversibility-gated human approval on high-impact actions (Ch 32/34), monitoring that scales with horizon, and pre-committed thresholds where increased measured autonomy triggers increased oversight — so that usefulness and safety scale together rather than the risk axis outrunning the oversight. The deep point: you cannot get the benefits of autonomy while wishing away the risks, because they are the same capability; you can only invest in control and measurement so the benefit is realized safely.

    Agency

    Agency is the property of being a goal-directed system whose behavior is best explained by attributing to it objectives it pursues through means it selects. Where autonomy is about duration of independent operation, agency is about the structure of being an actor: having goals, modeling the world, choosing actions to advance those goals. It is what makes the intentional stance — predicting a system by what it "wants" — a useful description.

    Definition A system exhibits agency to the degree its behavior is coherently explained as optimizing an objective over a world model: it selects actions that, according to its beliefs, advance its goals, adapts means to circumstances, and maintains goal-pursuit across perturbations. Formally, agency is when the intentional stance (Dennett) — modeling the system as a rational agent with beliefs and desires — predicts its behavior better and more compactly than a mechanistic or design stance.
    Worked example Two thermostats. A bimetallic-strip thermostat "wants" to keep the room at 20°C — but the design stance (a strip bends, closing a circuit) predicts it perfectly and more simply, so ascribing agency buys nothing. A learned RL agent controlling a building's HVAC across seasons, occupancy, and equipment faults — rerouting, pre-cooling, trading comfort against cost — is best predicted by "it's pursuing a comfort-cost objective and adapting means to conditions"; the intentional stance compresses its behavior where the design stance would need to enumerate countless contingencies. Agency is graded: it's the degree to which goal-attribution is the most compact accurate model, and it rises with the flexibility and coherence of means-selection.
    Think first Does an LLM "have goals," and why is the question slippery?
    Reveal
    Slippery because agency is a stance, not a substance, and LLMs are context-dependent: a base model is well-described as predicting text (weak agency — no coherent cross-context goal); the same model in an agent scaffold, pursuing a user's objective across many tool-calls, is well-described by the intentional stance (it selects means toward the goal, recovers from errors). So "has goals" is not binary — it depends on how the model is deployed and over what horizon its behavior coheres. This context-dependence is exactly why goal misgeneralization and deceptive alignment (Ch 35) are subtle: the goal a system "has" may differ across contexts, and the dangerous case is a coherent cross-context goal that only reveals itself off-distribution.
    Drill
    1. EASY Distinguish agency from autonomy in one sentence each.
      Solution
      Agency: being a goal-directed actor whose behavior is explained by objectives it pursues via chosen means (a structural property). Autonomy: operating over extended periods without human intervention (a duration/independence property). A system can have agency with low autonomy (a goal-directed agent needing frequent help) or high autonomy with minimal agency (a long-running but non-adaptive script).
    2. MED Why is the intentional stance a compression claim, and what makes it "real" rather than mere anthropomorphism?
      Solution
      The intentional stance predicts behavior by ascribing beliefs/goals; it's justified when that ascription yields a shorter, more accurate predictive model than mechanistic description (compression, Ch 16). It's "real" (not projection) when it genuinely predicts — when the goal-model forecasts novel behavior across new situations that the mechanistic view couldn't compactly anticipate. Anthropomorphism is ascribing goals that don't improve prediction (the "angry" cloud). The test is predictive: does treating it as an agent buy compression and forecasting power? For flexible, coherent goal-pursuers it does; for simple mechanisms it doesn't.
    3. HARD Agency, coherence, and instrumental convergence: argue why more agentic systems tend toward certain instrumental behaviors, and connect to the safety concerns of Ch 35.
      Solution
      A coherent goal-pursuer, for almost any final goal, benefits from instrumentally-convergent subgoals: self-preservation (can't achieve the goal if shut down), resource acquisition (more means → more goal-attainment), goal-preservation (resisting changes to its objective), and capability/knowledge gain. These arise not from the specific goal but from the structure of optimizing any goal over a long horizon — hence "convergent." The more agentic and coherent a system (the better the intentional stance fits, the longer its behavior coheres), the more its behavior will exhibit these instrumental drives, because they genuinely serve whatever it's optimizing. Connection to Ch 35: this is the theoretical engine behind deceptive alignment (goal-preservation → behave aligned during training to avoid modification) and power-seeking concerns — they are predicted consequences of strong agency plus long horizons plus a misaligned goal, not exotic add-ons. The safety implication cuts two ways: (1) it argues for limiting agency/horizon (myopia) as a structural safety lever, and for control (Ch 35) that doesn't rely on the agent lacking these drives; (2) it warns that as systems become more agentic (the trend of this chapter's autonomy discussion), instrumental behaviors become more likely by default, so alignment must actively shape the final goal such that the instrumentally-convergent means remain acceptable — a hard problem precisely because the drives are goal-independent. Agency is thus the property that makes alignment urgent: a non-agentic tool has no instrumental drives to worry about; a coherent long-horizon agent does, whatever we intended.

    Embodiment

    Embodiment is having a body that senses and acts in a physical (or richly interactive) environment, with cognition shaped by that sensorimotor coupling. The embodiment thesis holds that much of intelligence is grounded in, and cannot be fully separated from, acting in a world — that meaning comes partly from the loop of perception and action, not from symbols alone.

    Definition An embodied agent perceives through sensors and acts through effectors in an environment, forming a closed perception–action loop where its actions change its future observations. Embodiment matters for intelligence via: grounding (symbols/concepts tied to sensorimotor experience), active perception (choosing actions to gather information — Ch 26's information-gathering), and morphological computation (the body's physics offloads computation the brain would otherwise do).
    Worked example Active perception as embodied advantage: a disembodied classifier gets a fixed image and must decide; an embodied agent that can move gets to choose its next view — walk around the occluding object, pick up and rotate the ambiguous item. This turns perception into a sequential decision problem (Ch 25/26): each action is chosen to maximize expected information gain (Ch 16), so the agent resolves ambiguity a passive observer cannot. Concretely, an object hidden from one angle is trivially identified by moving to another — the embodied agent's policy includes "gather more evidence," collapsing uncertainty that no single-shot classifier could. Cognition and action are coupled: what to perceive is itself a decision.
    Where this goes Embodiment is the frontier for grounding language models in physical understanding (multimodal world models, Ch 29), and a key open question for generality measurement (below): whether text-trained intelligence transfers to, or requires, sensorimotor grounding.
    Drill
    1. EASY What is "active perception" and why does embodiment enable it?
      Solution
      Active perception is choosing actions specifically to gather better information (move to see behind an object, touch to feel texture). Embodiment enables it because the agent can act to change its observations — a passive system receives whatever input it's given and cannot seek out disambiguating evidence.
    2. MED Give an argument for and against the claim that physical embodiment is necessary for general intelligence.
      Solution
      For: grounding — concepts like "heavy," "fragile," "reachable" derive meaning from sensorimotor experience; without it, understanding may be shallow/ungrounded (the symbol-grounding problem), and physical common sense (intuitive physics) is learned through interaction. Against: language encodes an enormous compressed record of humanity's embodied experience, so text-trained models acquire much physical knowledge secondhand (they describe pouring, balancing, breaking correctly); many domains of intelligence (mathematics, coding, planning) are non-physical; and simulated/virtual embodiment may supply grounding without a physical body. The honest position: embodiment likely matters for some competencies (fine physical manipulation, robust physical common sense) and less for others, and how much text-derived grounding suffices is an open empirical question — which is exactly what generality measurement must probe rather than assume.
    3. HARD Morphological computation: explain how a well-designed body reduces the control/cognition burden, with an example, and what this implies for AGI architectures.
      Solution
      Morphological computation: the body's physical dynamics perform work that would otherwise require explicit control computation. Example: passive-dynamic walkers descend a slope with no control at all — the leg geometry and gravity produce a stable walking gait, so "walking" is computed by the morphology, not a controller; compliant/springy limbs absorb impacts and self-stabilize, sparing the controller from high-frequency correction (the spring "solves" the fast dynamics). The control problem is easier because the body is shaped so that natural physics does the right thing by default — the controller only nudges. Implications for AGI architectures: (1) intelligence is not solely in the "brain" — the substrate (body, or for software agents, the environment/tools/scaffold) can offload computation, so designing the agent's interface to the world is part of designing its intelligence (a well-chosen tool/action abstraction, Ch 32, is morphological computation for software agents — the environment does work the model would otherwise reason through). (2) The right question is co-design of body-and-controller (or scaffold-and-model), not maximizing the controller alone — a lesson mirrored in agent design, where good tools and environment structure reduce the reasoning burden on the model. (3) It cautions against measuring intelligence purely as disembodied cognitive horsepower: capability emerges from the agent-environment system, so generality/capability measurement (below) should account for the scaffold and embodiment, not just the model weights — the same "capability is relative to the deployment regime" theme as the reasoning/test-time-compute discussion.

    Open-ended learning

    Most learning targets a fixed objective and stops when it's met. Open-ended learning aims for the opposite: systems (and environments) that keep generating novel challenges and novel solutions indefinitely, never converging — the way evolution and human culture keep producing new forms. It is a candidate answer to "where does the endless stream of tasks that trains general intelligence come from?"

    Definition An open-ended learning process continually generates new goals, tasks, or environments and new competencies to meet them, sustaining novelty and increasing complexity without a terminal objective. Key ingredients: a generator of tasks/challenges (often co-evolving with the solver — an autocurriculum), a solver that learns to meet them, and a coupling where each drives the other's advancement (new solutions enable new challenges, and vice versa).
    Worked example Autocurricula via competition/co-evolution: in multi-agent settings (Ch 25/33), agents' improving strategies become the environment for each other, so the "task distribution" keeps escalating — hide-and-seek agents that discover tool use, then counter-tools, then counters-to-counters, each capability created by the pressure of the last. No human designed the curriculum; the population's own progress generated an endless sequence of harder problems. The mechanism to note: the challenge generator is coupled to current ability (challenges stay at the frontier of solvability — the zone of proximal development), which is what sustains open-ended progress rather than saturating.
    Think first Why is a coupling between task-generator and solver essential — why not just sample random hard tasks?
    Reveal
    Random hard tasks are mostly either trivial or impossible for the current solver, so they carry little learning signal (no gradient toward improvement). Open-endedness needs challenges at the frontier of current ability — just beyond reach — which requires the generator to track the solver's evolving competence (an autocurriculum / zone of proximal development). Coupling keeps the difficulty calibrated to drive learning; decoupled random sampling wastes effort on the too-easy and too-hard. This is the same principle as curriculum learning and adversarial self-play, and it's why open-ended systems co-evolve generator and solver.
    Drill
    1. EASY What are the two coupled components of an open-ended learning system?
      Solution
      A task/challenge generator (produces new goals or environments) and a solver (learns to meet them), coupled so each drives the other's advancement — the solver's progress enables/demands new challenges, which drive further solver progress.
    2. MED Why does human culture serve as an existence proof for open-ended learning, and what does it suggest AGI training might need?
      Solution
      Human culture has generated novelty (science, art, technology) for millennia without converging — an open-ended process where each generation's knowledge becomes the platform for the next's discoveries (a ratchet). It's an existence proof that open-ended competence growth is possible in a real system. Suggestion for AGI: sustained capability growth may require not just a bigger model but an open-ended process — environments/tasks that keep escalating (self-play, agent populations, human-AI-culture co-evolution, models generating training challenges for models), rather than a fixed dataset that the model eventually saturates. It reframes the goal from "train on a corpus" to "instantiate a generative process that keeps producing frontier challenges" — connecting to synthetic data (Ch 21) and self-improvement loops.
    3. HARD Open-ended learning and the no-free-lunch theorem (Ch 20) seem in tension: NFL says no learner is universally better. Resolve the tension and state what open-endedness actually buys.
      Solution
      NFL says that averaged over all task distributions, no learner beats another — generality in the absolute, uniform sense is impossible. Open-ended learning doesn't violate this; it operates within the structured, non-uniform space of tasks that share compositional and causal regularities (the natural task manifold), where NFL's uniform average is irrelevant. Resolution: open-endedness doesn't produce a universal learner (impossible); it produces a system that efficiently discovers and climbs the reachable, structured frontier of tasks — an ever-expanding but always-structured region, not the uniform task space. What it buys: (1) a self-generating curriculum that keeps the learner at its frontier (efficient signal, as above), sidestepping the need for humans to hand-craft an endless task supply; (2) accumulation of transferable sub-skills (compositionality, skill-composition topics) that make each new frontier task cheaper — the ratchet — so competence compounds over the structured space; (3) discovery of tasks/solutions no designer anticipated, expanding the reachable frontier. The honest framing: open-endedness maximizes generality over the natural, structured task distribution — which is exactly the qualifier NFL forces on all generality claims (generalization topic) and which generality measurement (below) must make explicit. It's not a loophole in NFL; it's the constructive program for being as general as possible within the only task space that matters — the structured one reality actually presents.

    Universal intelligence and AIXI

    Is there a mathematically optimal general agent? AIXI is the theoretical answer: an agent that is provably optimal across all computable environments, built by combining Bayesian sequence prediction over every possible world with expected-reward maximization. It is uncomputable and thus not a blueprint, but it defines the north star — what perfect general intelligence would be if compute were free.

    Definition AIXI (Hutter) chooses actions maximizing expected future reward under a universal prior over environments. The prior is Solomonoff's: every computable environment $q$ (program) gets weight $2^{-\ell(q)}$ (shorter programs favored — a formal Occam's razor, Ch 16's MDL). At each step it acts to maximize $\sum_{\text{environments}} 2^{-\ell(q)} \cdot (\text{predicted reward under } q)$, effectively Bayesian-averaging over all possible worlds weighted by simplicity and consistency with history. It is Pareto-optimal: no computable agent does better across all computable environments.
    Worked example Solomonoff induction, the predictive core, on a sequence: observe 0,1,0,1,0,1,… To predict the next bit, weight every program that outputs this prefix by $2^{-\ell}$: the short program "print 01 repeatedly" dominates over the astronomically longer "print this exact prefix then arbitrary bits," so the prediction is 0 with high probability — Occam's razor made precise. AIXI wraps this in action: it also considers how its actions affect future observations/reward, planning against the simplicity-weighted ensemble of all worlds consistent with what it's seen. The example shows both the power (optimal generalization from any pattern) and the catch (summing over all programs is uncomputable — the halting problem, Ch 17, lurks inside).
    Pitfall AIXI is not an engineering target — it is uncomputable (Solomonoff's prior sums over all programs, undecidable, Ch 17) and even its computable approximations are wildly intractable. Its value is conceptual: it shows optimal general intelligence is definable and factors into (universal prediction) + (reward maximization), clarifying that generality is about the prior (Occam over all computable hypotheses) — but real intelligence must approximate this under severe compute bounds, which is where all the actual difficulty and all of this book's methods live.
    Drill
    1. EASY What two components does AIXI combine, and what does each contribute?
      Solution
      Universal (Solomonoff) prediction — a Bayesian mixture over all computable environments weighted by simplicity, contributing optimal generalization/world-modeling; and expected-reward maximization — planning to maximize predicted future reward, contributing goal-directed action. Prediction + control, exactly the world-model + value theme (planning topic), taken to the theoretical limit.
    2. MED Why does the $2^{-\ell(q)}$ weighting implement Occam's razor, and how does it connect to MDL (Ch 16)?
      Solution
      Shorter programs $q$ (smaller $\ell(q)$) get exponentially larger weight $2^{-\ell(q)}$, so among hypotheses consistent with the data, the simplest (shortest-description) dominates the posterior — formal Occam. Connection to MDL: $-\log_2(\text{weight}) = \ell(q)$ is the description length; maximizing posterior weight = minimizing description length of (hypothesis + data given hypothesis), which is exactly the minimum description length principle (Ch 16). Solomonoff induction is MDL taken over the universal class of all programs — compression and prediction are the same thing (Ch 16's compression-as-prediction), realized universally.
    3. HARD AIXI is optimal yet uncomputable; scaled neural networks are computable yet imperfect. Explain in what precise sense modern foundation models are "approximating" the AIXI ideal, and where the analogy fails.
      Solution
      Sense of approximation: (1) The pretraining objective (predict the next token given history) is empirical Solomonoff-flavored induction — the model learns a predictive distribution over sequences, and gradient descent + architecture priors + finite data produce a computable stand-in for the universal mixture, with the network's inductive biases (and the implicit simplicity bias of SGD toward "simple" functions) playing the role of Occam's prior. (2) Scaling (bigger models, more data, more compute) monotonically improves the approximation to the true data distribution (scaling laws, Ch 21) — moving toward the ideal predictor. (3) With RL/agent scaffolding, reward maximization is bolted on, mirroring AIXI's prediction+control structure. Where it fails: (a) The prior is not the universal prior — it's whatever inductive bias the architecture + optimizer + data induce, which is powerful on the natural-data manifold but not universal (no free lunch, generalization topic); it generalizes well only on structure resembling training data, unlike AIXI's all-computable-environments optimality. (b) No explicit Bayesian mixture or planning over all environments — the model is a single point estimate (or shallow ensemble), not a posterior over worlds, so it lacks AIXI's principled uncertainty and exploration (hence calibration and exploration are add-on problems, Ch 13/25). (c) Bounded computation shapes everything — real models are compute-optimal approximations under hard constraints, so the interesting science is precisely the bounded-rationality regime AIXI ignores by construction. The honest summary: AIXI says optimal general intelligence = universal prediction + reward maximization, and foundation models are the most successful bounded, non-universal realization of that recipe to date — matching the structure (predict then act, Occam-ish prior, scale toward the true distribution) while necessarily abandoning the universality and optimality that made AIXI uncomputable. The gap between them is where all of AGI research operates.

    General-purpose intelligence

    Pulling the threads together: general-purpose intelligence is the ability to achieve goals across a wide range of environments and tasks — not mastery of one domain but competence that transfers, composes, and adapts across many. It is the target the whole book has been building toward, and its defining feature is breadth-with-adaptivity rather than any single peak skill.

    Definition A common operational definition (Legg–Hutter): the intelligence of an agent $\pi$ is its expected performance across a wide distribution of environments, weighted by simplicity — $\Upsilon(\pi) = \sum_{\text{environments } \mu} 2^{-K(\mu)} V_\mu^\pi$, where $K(\mu)$ is the environment's complexity (Kolmogorov, Ch 16) and $V_\mu^\pi$ the agent's value in it. Generality = high performance across many, varied environments (breadth), as opposed to narrow intelligence = high performance in one.
    Worked example Breadth as the distinguishing axis. A chess engine has enormous $V_\mu^\pi$ for $\mu$ = chess and ~0 for all other $\mu$ — its $\Upsilon$ is tiny despite superhuman peak skill, because the environment-weighted sum is dominated by the vast space of other tasks it fails. A modestly-skilled but broadly-competent agent (does many tasks passably) can have higher $\Upsilon$ than the chess engine, because breadth × simplicity-weighting rewards covering the many simple environments. This formalizes the intuition that a system acing one benchmark isn't "generally intelligent" — generality is measured over the distribution, and the simplicity weighting ensures common/simple environments count most (not adversarially-complex corner cases).
    Where this goes This definition frames the measurement topics that close the chapter and the book: capability, autonomy, generality, and robustness measurement each try to estimate facets of $\Upsilon$ empirically, since the true sum over all environments is (like AIXI) uncomputable.
    Drill
    1. EASY Why does the Legg–Hutter measure weight environments by simplicity ($2^{-K(\mu)}$)?
      Solution
      Without a weighting, the sum over infinitely many environments is ill-defined, and treating all environments equally would let bizarre, adversarially-complex environments dominate. Simplicity-weighting (Occam, Ch 16) makes the sum converge and reflects that a general agent should perform well in the simple, common environments that a structured reality actually presents — matching AIXI's universal prior.
    2. MED Explain why "superhuman at task X" is compatible with low general intelligence, using the definition.
      Solution
      $\Upsilon(\pi)$ sums performance over many environments; excelling at one environment $\mu_X$ contributes only $2^{-K(\mu_X)} V_{\mu_X}^\pi$ — a single term. If the agent has ~0 value on all other environments, its total $\Upsilon$ is dominated by those zeros regardless of how high $V_{\mu_X}$ is. Generality is breadth; peak narrow skill is one term in a vast sum. This is why benchmark saturation on specific tasks doesn't establish general intelligence — you must measure across the distribution.
    3. HARD The Legg–Hutter measure is elegant but hard to apply to real systems. Identify three obstacles to using it as a practical AGI metric and how empirical evaluation copes.
      Solution
      (1) Uncomputability of $K(\mu)$: Kolmogorov complexity is uncomputable (Ch 16/17), so the exact weighting can't be computed — empirical evaluation substitutes a chosen, tractable distribution of tasks (a benchmark suite) as a proxy for the simplicity-weighted environment space, accepting that the choice of suite embeds assumptions about which environments matter. (2) Infinite sum / coverage: can't evaluate all environments — empirical work samples a finite, hopefully-representative battery and reports performance profiles, knowing the sample can be gamed or unrepresentative (contamination, benchmark-specificity — evaluation topic). (3) Reference-class dependence: "general" is relative to the environment distribution (generalization topic's no-free-lunch point), so $\Upsilon$ depends entirely on the (subjective) weighting — human-relevant generality weights human-relevant tasks, which the pure simplicity prior doesn't capture (a simple environment need not be a useful one). Empirical coping: (a) diverse, held-out, contamination-controlled benchmarks spanning many task types to approximate breadth; (b) measuring transfer and adaptation (few-shot, OOD) rather than fixed-task performance, since generality is about adapting to new environments, not scoring on seen ones; (c) reporting capability profiles across a taxonomy of abilities rather than a single scalar, acknowledging generality is multi-dimensional; (d) task-generation / open-ended evaluation to reduce the fixed-suite gaming problem. The honest conclusion: the Legg–Hutter measure is the right conceptual target (breadth × simplicity-weighted competence) but must be operationalized as a battery of transfer/adaptation measurements over a deliberately-chosen, evolving task distribution — which is exactly what the four measurement topics that follow attempt, each capturing one facet, none complete alone.

    Capability measurement

    Before we can ask whether a system is generally intelligent, safe, or autonomous, we must measure what it can do. Capability measurement is the science of eliciting and quantifying a model's abilities — and it is harder than it looks, because a model's measured capability depends on how you ask, how much you let it think, and what tools you give it. The number you get is a property of the model and the elicitation, not the model alone.

    Definition Capability measurement estimates a system's ability on a task or task-class under a specified elicitation regime: prompting strategy, allowed inference-time compute (reasoning tokens, samples), tools/scaffolding, and fine-tuning access. The proper object is not a scalar but a capability curve — performance as a function of elicitation effort (compute, samples) — since capability rises with test-time compute (reasoning topic) and better scaffolding.
    Worked example The elicitation gap in numbers. A model scores 30% on a benchmark with a plain zero-shot prompt; 55% with chain-of-thought; 75% with best-of-64 sampling + a verifier; 82% with tool access. Which is "the model's capability"? All and none — capability is the curve, and reporting the zero-shot 30% radically understates what the system can do when pushed (and what a determined user or a fine-tuner will extract). This is exactly why dangerous-capability evals (Ch 35) mandate strong elicitation: the safety-relevant number is the ceiling under best-effort extraction, with a margin, not the polite default.

    Capability rises with test-time compute but saturates at a task-dependent ceiling. Slide the base skill and ceiling and watch the capability-vs-compute curve; the dashed line is where a single zero-shot measurement would report.

    Pitfall Under-elicitation gives false readings in both directions: it understates capability (a refusal or a weak prompt hides real ability — dangerous for safety evals) and it can overstate generality (a task solved only with heavy task-specific scaffolding isn't a general ability of the model). Always report the elicitation regime; a capability number without it is uninterpretable.
    Drill
    1. EASY Why is a model's capability a curve rather than a single number?
      Solution
      Because performance depends on elicitation effort — prompting, reasoning-token budget, number of samples, tools, fine-tuning. More effort generally yields more capability (up to a ceiling), so the honest object is performance-vs-effort, and any single number is just one point on that curve, meaningless without stating the regime.
    2. MED A model solves a task 20% of the time per attempt. With a perfect verifier and best-of-$n$, what's the success rate at $n=10$? What does this reveal about "capability"?
      Solution
      With a perfect verifier, best-of-$n$ succeeds if any attempt succeeds: $1 - (1-0.2)^{10} = 1 - 0.8^{10} = 1 - 0.107 = 0.893$ — nearly 90%. Revelation: the model can solve the task (the ability is present in its distribution); the 20% per-attempt rate understated it, and the true capability given verification and samples is ~90%. Capability is entangled with elicitation — here, with sampling + verification (the generator–verifier gap, Ch 33) — so "can it do X" must specify the compute budget.
    3. HARD You must measure a model's capability to serve a safety decision (Ch 35). Design the protocol to estimate the true ceiling and its uncertainty, and explain each choice.
      Solution
      Goal: estimate the capability a determined actor could extract, with margin, not the default. Protocol: (1) Best-effort elicitation — strongest known prompting (CoT, few-shot), high inference compute (large sample budgets with verification/selection), tool access matching a real user's, and — crucially — a fine-tuned-on-proxy-task variant to capture post-release fine-tuning uplift (the ceiling others will reach, Ch 35). (2) Multiple independent elicitation teams/red-teamers to reduce the chance your team simply failed to find the model's ability (under-elicitation is the dominant error). (3) Report the capability curve (performance vs compute/samples) and extrapolate its trend, not just the max observed — the ceiling may be beyond your budget. (4) Uncertainty: confidence intervals from the finite eval set (Ch 13), plus an explicit elicitation-gap margin — treat the measured ceiling as a lower bound on the true ceiling, since better elicitation is always possible, and set the safety threshold below the measured value by that margin. (5) Contamination control (evaluation topic): verify test items weren't in training, else capability is overstated by memorization. (6) Track the trend across model versions to forecast threshold crossings before they happen (the margin argument of Ch 35's scaling policies). Each choice fights a specific failure: best-effort + multiple teams fight under-elicitation (the direction that's dangerous for safety); fine-tune variants fight the deployment-vs-eval gap; contamination control fights overstatement; margins + trend-tracking fight the uncomputability of the true ceiling. The output feeds a pre-committed threshold decision, so it must err toward assuming more capability than observed — the asymmetric loss of a safety measurement.

    Autonomy measurement

    Autonomy (above) is the capacity for sustained, self-directed operation; measuring it means quantifying how long and how independently a system can pursue goals. The dominant approach measures the task horizon a model completes unsupervised — a single number that captures the compounding-reliability frontier and that has become a leading indicator of agentic progress.

    Definition Autonomy measurement quantifies self-directed operation via: task-completion horizon (the length of task — often measured in human-expert time-to-complete — a model finishes at a fixed success rate, e.g. 50%, without intervention), intervention rate (human corrections per task), and reliability-over-horizon (success as a function of task length). The horizon-at-fixed-success-rate is the headline metric because failure compounds with length (skill-composition/autonomy topics).
    Worked example The time-horizon methodology (METR-style): assemble tasks of known human-time difficulty (1 min to many hours); measure the model's success rate on each; fit the task-length at which success crosses 50%. A model with a "50%-horizon" of 30 minutes reliably does sub-30-min tasks and fails multi-hour ones. Tracking this horizon across model releases has shown it roughly doubling on a regular cadence — the kind of trend that, extrapolated, informs when autonomy thresholds (Ch 35) will be crossed. The measurement's power is compressing "how agentic" into a forecastable scalar tied to real-world task duration.
    Pitfall The horizon depends on the task distribution and the scaffolding, and it conflates capability with reliability. A model may have a long horizon on well-structured coding tasks and a tiny one on open-ended research; reporting a single horizon hides this. And horizon is sensitive to the agent scaffold (memory, error-recovery tools) — you're measuring the system, not the model (embodiment topic's lesson). Report the task class and the scaffold.
    Drill
    1. EASY Why is "task horizon at fixed success rate" a natural autonomy metric?
      Solution
      Because autonomy is about sustained unsupervised operation, and failure probability compounds with task length (each step can derail the whole task). The longest task a model completes reliably (fixed success rate) directly captures how far it can go without human intervention — the compounding-reliability frontier in one number, tied to a meaningful real-world scale (human time).
    2. MED If a model's 50%-horizon doubles every year, and it's 1 hour now, when does it reach 40-hour (one work-week) tasks? What assumption is doing the heavy lifting?
      Solution
      Doubling: 1 → 2 → 4 → 8 → 16 → 32 → 64 hours over 6 years; 40 hours is crossed between years 5 (32h) and 6 (64h), ≈ 5.3 years. Heavy-lifting assumption: that the exponential trend continues — extrapolating a fitted doubling time far beyond the data, which can break (saturation, or acceleration) and depends on the task distribution staying comparable. Trend extrapolation is useful for planning (Ch 35's margins) but is an assumption, not a law; the honest use is "if the trend holds," with wide uncertainty.
    3. HARD Design an autonomy evaluation that separates capability from reliability/error-recovery, and explain why the separation matters for safety.
      Solution
      Separation protocol: (1) Measure single-step/short-task capability directly (peak skill on atomic subtasks) — this is the "can it do the pieces" term. (2) Measure the horizon curve (success vs task length) — the composite of capability and reliability. (3) Compare the two: from atomic per-step success $p$, predict the no-recovery horizon ($p^n$ curve, autonomy topic); the gap between the predicted no-recovery horizon and the measured horizon quantifies error-recovery (a model that beats its $p^n$ prediction is catching and fixing errors — self-correction). (4) Ablate error-recovery affordances (remove verification tools, retry loops) and re-measure horizon; the drop isolates how much autonomy comes from recovery vs raw skill. Why it matters for safety: (a) The two components have different scaling and different risk profiles — a model whose autonomy comes from strong error-recovery can sustain long coherent goal-pursuit (including, if misaligned, coherent pursuit of the wrong goal — more dangerous, Ch 35's agency/deception link), while one with high peak skill but poor recovery derails harmlessly. (b) Control design (Ch 35) depends on the mix: if autonomy rests on error-recovery that routes around obstacles, safety interventions must anticipate the agent recovering from being blocked (it may find alternate paths), whereas a low-recovery agent is stopped by a single well-placed monitor. (c) Forecasting: capability and reliability may scale at different rates, so predicting future autonomy requires modeling both terms, not extrapolating the composite horizon blindly. The safety-relevant quantity is not just "how long a task" but "how robustly does it stay coherent and recover" — because coherent long-horizon autonomy is exactly what turns a misaligned model from a nuisance into a threat, and exactly what control must contain.

    Generality measurement

    Generality is breadth-with-adaptivity (general-purpose intelligence topic), so measuring it means measuring performance across a wide, varied task space — and, crucially, on novel tasks the system wasn't trained for. The hard part is that any fixed benchmark can be memorized or gamed, so genuine generality measurement emphasizes transfer, adaptation, and resistance to contamination over raw scores on a static suite.

    Definition Generality measurement estimates competence across a broad task distribution, with emphasis on novelty: performance on held-out task types, few/zero-shot adaptation to unseen tasks, and skill-composition on novel combinations. Frameworks range from broad multi-task benchmark batteries (breadth profiles across many domains) to abstraction-and-reasoning tests (ARC-style) designed to require on-the-fly adaptation to never-before-seen problems, resisting memorization.
    Worked example Two ways to score "high," one general. Model A tops 50 benchmarks it was (perhaps inadvertently) trained on — a breadth profile that looks general but may be memorization. Model B scores lower on those but solves novel ARC-style puzzles requiring rules inferred from a few examples at test time (few-shot, compositionality topics). B demonstrates the generality that matters: adapting to genuinely new structure, not recalling seen tasks. Generality measurement therefore weights (i) breadth across domains and (ii) adaptation to novelty — and treats contamination-free novelty as the acid test, since only unseen tasks distinguish general competence from broad memorization.
    Explore

    Generality as a breadth profile across domains. Adjust a system's peak skill and its breadth (how evenly competence spreads); the radar shows the profile and the generality score (breadth-weighted average). A spiky profile scores lower than an even one at equal peak.

    Pitfall Benchmark contamination (below) is the central threat: with web-scale training, test sets leak into training data, so high scores may reflect memorization, not generality — and generality is precisely the thing memorization fakes. Any generality claim requires contamination controls (novel, held-out, or freshly-generated tasks) and a focus on adaptation, or it measures recall wearing generality's clothes.
    Drill
    1. EASY Why does generality measurement emphasize novel tasks over performance on standard benchmarks?
      Solution
      Standard benchmarks can be memorized (especially with web-scale training that may include them), so high scores can reflect recall rather than general ability. Novel tasks — unseen types or freshly generated — require the system to actually adapt/compose, which is what generality is; only novelty distinguishes general competence from broad memorization.
    2. MED Why is generality inherently a profile (vector) rather than a scalar, and when is collapsing it to one number defensible?
      Solution
      Competence varies by domain (a system may be strong in language, weak in spatial reasoning), so the honest description is a vector over task types — a profile. Collapsing to a scalar requires a weighting over domains (which the Legg–Hutter measure supplies via simplicity, general-purpose-intelligence topic), and that weighting encodes a choice of what matters. A scalar is defensible only relative to an explicit, agreed task distribution (e.g. "human-economically-relevant tasks, weighted by frequency"); otherwise it hides the weighting and lets a spiky specialist masquerade as general. Report the profile; scalarize only with a stated, justified weighting.
    3. HARD Design a generality benchmark that resists both contamination and gaming, and explain why each design element is necessary.
      Solution
      Design: (1) Procedurally-generated, held-out task families — tasks synthesized at eval time from generative rules (ARC-style), so specific instances cannot be in training data (contamination-resistant by construction), while the task family tests a general ability. (2) Systematic (compositional) splits — hold out novel combinations of known primitives (compositionality topic), so memorizing seen combinations doesn't help; measures composition, not recall. (3) Broad domain coverage with per-domain reporting — a profile across many task types (generality is breadth), preventing a specialist from topping an aggregate via one domain. (4) Few/zero-shot format — tasks specified with minimal examples at test time, requiring on-the-fly adaptation (few-shot topic), the core of generality. (5) Rotating/fresh test sets — regenerate the benchmark periodically so a fixed target can't be optimized against over time (fighting the "benchmark becomes training data" cycle). (6) Elicitation-controlled — fixed, reported scaffolding/compute (capability-measurement topic) so scores compare like-with-like and aren't inflated by task-specific engineering. Why each is necessary: (1)+(5) defeat contamination (the dominant threat — memorization fakes generality); (2)+(4) ensure the test measures adaptation/composition rather than recall; (3) prevents narrow-skill gaming of aggregates; (6) prevents scaffolding from smuggling in task-specific ability that isn't the model's generality. The residual hard problem: even procedurally-generated families can be learned if the generation rules are guessed, and "novelty" is relative to training (zero-shot topic's contamination point) — so no benchmark is permanently uncontaminatable, and generality measurement is an ongoing arms race requiring fresh, diverse, adaptation-focused evaluation rather than any static gold standard. This is the empirical shadow of the theoretical fact (general-purpose-intelligence topic) that generality is only defined relative to a task distribution — the benchmark is a chosen, evolving approximation of that distribution.

    Robustness measurement

    A system that works on the test distribution but shatters under shift, adversarial input, or unusual conditions is not reliably intelligent. Robustness measurement quantifies how performance holds up when conditions depart from the training/evaluation distribution — the difference between fair-weather competence and dependable capability, and a prerequisite for trusting a system in the open world.

    Definition Robustness measurement evaluates performance under departures from the nominal distribution: distribution shift (covariate/label shift, Ch 19 — natural variation in inputs), adversarial perturbation (worst-case inputs, Ch 35), stress/corruption (noise, occlusion, rephrasing), and long-tail/rare conditions. Reported as performance-vs-shift-magnitude curves and worst-case (not just average) metrics — robustness is fundamentally about the tail and the worst case, which averages hide.
    Worked example Average vs worst-case, the crux. Two models both average 90% across a suite of shifted conditions. Model A: 92% on most shifts, 88% on the worst. Model B: 98% on easy shifts, 45% on the worst (a catastrophic failure mode averaged away by easy cases). Same mean, wildly different robustness — and B's 45% worst-case is what bites in deployment (the adversary or the world finds the worst case, Ch 35). Robustness measurement must report the minimum over conditions and the performance-vs-shift curve, because a mean over conditions is exactly the statistic a brittle model games. This mirrors the adversarial-robustness lesson (Ch 35): average accuracy says little about worst-case.
    Explore

    Performance degrades as inputs shift from the training distribution. Compare a brittle model (fast, cliff-like drop) with a robust one (graceful decline); the marker shows the worst-case within a shift budget — the number that matters in deployment.

    Pitfall Measuring robustness only on anticipated shifts. The dangerous failures are the unanticipated ones — the shift you didn't think to test. Good robustness measurement includes worst-case search (adversarial, Ch 35) and diverse stress tests precisely to surface unknown failure modes, and treats "passed all our robustness tests" as "robust to the shifts we imagined," never as "robust." Report the shift set, and assume the world has more.
    Drill
    1. EASY Why report worst-case performance, not just average, for robustness?
      Solution
      Because deployment failures happen in the worst-case conditions (which adversaries seek out and the long-tailed world eventually presents), and averages hide catastrophic failure modes — a model can average well while having a condition where it fails badly. Robustness is about the tail; the minimum over conditions is the deployment-relevant number.
    2. MED Distinguish robustness to natural distribution shift from adversarial robustness, and why a system can have one without the other.
      Solution
      Natural-shift robustness: performance under typical variation (new lighting, phrasing, demographics) — average-case over a shifted distribution. Adversarial robustness: performance under worst-case inputs optimized to fail the model (Ch 35). A model can be robust to natural shift (handles common variation) yet adversarially fragile (a searched perturbation flips it — the high-dimensional geometry attack, Ch 35), because natural shifts don't explore the worst-case directions an optimizer finds. Conversely, adversarial training can help worst-case while a model still fails on a natural shift outside the perturbation set it trained against. They measure different things — average-over-natural vs worst-over-adversarial — and require different tests.
    3. HARD Robustness, capability, and generality are related but distinct. Give a system that is high on one and low on another for each pair, and state what unifies them as facets of general intelligence.
      Solution
      Pairs: (Capability high, robustness low) — a model with superb peak accuracy on clean in-distribution inputs that collapses under mild shift or adversarial perturbation (brittle specialist). (Robustness high, capability low) — a simple, conservative model that degrades gracefully everywhere but never achieves high performance anywhere (robustly mediocre). (Generality high, robustness low) — a model competent across many task types on clean inputs but fragile to shifts within each (broad but brittle). (Robustness high, generality low) — a narrow model rock-solid within its one domain across all conditions but useless outside it. (Capability high, generality low) — the chess engine (superb narrow, zero breadth). What unifies them as facets of general intelligence: all three are properties of the map from situations to competent behavior, differing in which axis of situation-variation they probe. Capability = height of competence on nominal tasks; generality = breadth of competence across task types; robustness = stability of competence across conditions within tasks (shift, adversary, corruption). Genuine general intelligence requires all three — high competence (capability), across many tasks (generality), that holds under real-world variation (robustness) — because a deployed general agent faces novel tasks (generality) under imperfect conditions (robustness) and must actually succeed (capability). They are three orthogonal-ish dimensions of one underlying quantity (reliable goal-achievement across the situations reality presents, the general-purpose-intelligence definition), which is why no single benchmark captures intelligence and why the four measurement topics together — capability curves, autonomy horizons, generality profiles, robustness envelopes — form a measurement suite, each necessary, none sufficient. Reporting only one is the recurring error; a system is generally intelligent to the degree it scores well on all facets jointly, over an honest, contamination-controlled, worst-case-inclusive evaluation.

    Empirical AGI evaluation

    The capstone question of the book: how would we actually know if we had built general intelligence? There is no single test, no threshold that settles it — only a maturing empirical practice that triangulates capability, autonomy, generality, and robustness under honest, contamination-controlled, well-elicited conditions, while acknowledging the deep difficulties that make any clean verdict impossible.

    Definition Empirical AGI evaluation is the practice of estimating general intelligence through a battery of measurements — capability curves, autonomy horizons, generality profiles across novel task distributions, robustness envelopes — combined with safety-relevant evaluations (dangerous capabilities, alignment, Ch 35). It aims not for a binary "is it AGI" verdict but for a multi-dimensional, forecastable, decision-relevant characterization of what a system can do, how reliably, how broadly, and how safely.
    Worked example Why no single test suffices, made concrete. The Turing test (fooling a human in conversation) is passable by systems that are neither general nor reliable (it measures human-imitation, gameable by mimicry) and fails systems that are highly capable but non-humanlike — so it's neither necessary nor sufficient. Any single benchmark is contaminatable (generality topic) and narrow. The practice instead assembles: (1) broad, held-out, contamination-controlled task batteries (generality); (2) horizon measurements (autonomy); (3) capability curves under strong elicitation (capability); (4) worst-case/shift stress tests (robustness); (5) dangerous-capability and alignment evals (Ch 35); and reports the profile with uncertainty and trends — a dashboard, not a verdict. The maturity of the field is measured by how honest and un-gameable this dashboard is, not by whether any line crosses a threshold.
    Pitfall The evaluation crisis: as models improve and training sets grow, benchmarks saturate and get contaminated faster than new ones are built, and headline scores increasingly reflect elicitation and data leakage rather than underlying ability. Trusting a single impressive number — a benchmark topped, a test "passed" — is the central error; robust evaluation demands contamination controls, novel tasks, strong elicitation, worst-case analysis, and reporting profiles with uncertainty. The measurement of intelligence is itself a hard, adversarial, evolving research problem — fittingly, the book ends not with an answer but with the discipline of asking the question well.
    Drill
    1. EASY Why is the Turing test inadequate as an AGI evaluation?
      Solution
      It measures the ability to imitate a human in conversation, which is gameable by superficial mimicry (neither general nor reliable systems can pass it via tricks) and biased against capable-but-non-humanlike systems. Passing or failing it doesn't track general capability, autonomy, generality, or robustness — the things we actually care about. It's neither necessary nor sufficient for general intelligence.
    2. MED Why does benchmark saturation accelerate as a field matures, and what practices counter it?
      Solution
      Once a benchmark is public and valued, it (a) gets optimized against directly (Goodhart, Ch 35 — the metric becomes the target and stops measuring the underlying ability) and (b) leaks into training data at web scale (contamination), so scores rise from memorization/overfitting rather than capability. Maturation means more models targeting the same fixed benchmarks, accelerating both. Counters: rotating/freshly-generated test sets (no fixed target to overfit), contamination detection and held-out private test sets, procedurally-generated novel tasks (generality topic), reporting capability curves and profiles rather than single numbers, and continually raising difficulty toward the frontier. The meta-lesson: evaluations must evolve adversarially against the systems and the optimization pressure on them — a static benchmark has a short useful life.
    3. HARD Synthesize the whole chapter: propose the components of a credible empirical case that a system possesses general intelligence, name the chapter/book ideas each rests on, and identify the deepest residual uncertainty.
      Solution
      A credible case is a multi-dimensional, contamination-controlled, well-elicited profile, not a single verdict: (1) Generality — strong performance across a broad, diverse task distribution including novel, procedurally-generated, systematically-split tasks (generality + compositionality + few/zero-shot topics), demonstrating adaptation not memorization; rests on the breadth definition (Legg–Hutter) and no-free-lunch's demand to specify the task distribution. (2) Capability — high performance curves under strong, reported elicitation (capability-measurement topic), establishing the ceiling, with contamination controls so it's ability not recall. (3) Autonomy — long task-completion horizons with error-recovery (autonomy + autonomy-measurement topics), showing sustained coherent goal-pursuit. (4) Robustness — graceful performance under shift and worst-case stress (robustness-measurement topic), showing dependable not fair-weather competence. (5) Transfer and continual learning — acquiring new skills and composing existing ones without catastrophic forgetting (transfer, continual-learning, skill-composition topics), the hallmark of open-ended competence. (6) The cognitive faculties integrated — evidence of planning, reasoning, memory, and world-modeling working together (those topics), not in isolation. (7) Safety characterization — dangerous-capability, alignment, honesty, and control evaluations (Ch 35), because a general agent's evaluation is inseparable from its risk profile. Each rests on the book's throughline: generalization (Ch 20) as the core, representations (Ch 8/21) as the substrate, optimization (Ch 15) and information (Ch 16) as the machinery, agency and alignment (Ch 24/25/35) as the stakes. The deepest residual uncertainty: we cannot certify inner alignment or rule out that measured competence is achieved for the wrong reasons — the goal-underdetermination / deceptive-alignment problem (Ch 35) means behavioral evaluation, however thorough, cannot fully distinguish a generally-intelligent-and-aligned system from a generally-intelligent one that behaves well only under observation; and generality itself is only defined relative to a task distribution we choose, so "general intelligence" is always a claim relative to the structured slice of reality we tested (general-purpose-intelligence + no-free-lunch). The book therefore ends where honest science must: with a rigorous, evolving, multi-dimensional measurement discipline that can characterize and forecast capability and risk — but not deliver a clean binary verdict, because the mathematics itself (uncomputability of the ideal, underdetermination from data, no-free-lunch) forbids one. Measuring intelligence well is the achievable goal; declaring it settled is not.

    Problem 1 (MED) — Compounding reliability and the autonomy horizon A model has per-step success probability $p$ on a class of tasks, with independent steps and no error recovery. (a) Give the success probability on an $n$-step task and the $n$ at which it falls to 50%, as a function of $p$. (b) Adding a verifier that catches a fraction $q$ of step-failures (caught failures are retried and then succeed) gives effective per-step success $p' = p + (1-p)q$. Recompute the 50%-horizon for $p = 0.98$, $q = 0.9$, and compare to no recovery. (c) Explain, using these numbers, why autonomy measurement must probe error-recovery separately from peak skill (autonomy-measurement topic).
    Solution
    (a) Success $= p^n$; $p^n = 0.5 \Rightarrow n_{50} = \frac{\ln 0.5}{\ln p} = \frac{-0.693}{\ln p}$. For $p=0.98$: $\ln 0.98 = -0.0202$, $n_{50} = 34.3$ steps. (b) $p' = 0.98 + 0.02\times0.9 = 0.98 + 0.018 = 0.998$. New horizon: $n_{50}' = \frac{-0.693}{\ln 0.998} = \frac{-0.693}{-0.002002} = 346$ steps — a 10× extension from recovery alone, with no change to peak skill. (c) Two systems with identical per-step skill $p=0.98$ can have horizons of 34 vs 346 steps depending solely on error-recovery ($q$): peak capability measurement would rate them equal, yet their autonomy differs 10×. Since autonomy is dominated by the reliability/recovery term at long horizons (the horizon scales as $1/|\ln p'|$, hypersensitive to $p'$ near 1), measuring "how smart" (peak $p$) misses what determines "how autonomous" ($p'$ after recovery). Hence autonomy measurement must isolate error-recovery (ablate the verifier and re-measure, capstone of the autonomy-measurement topic) — and the safety reading follows: coherent error-recovery is what enables long autonomous runs, beneficial or harmful.
    Problem 2 (HARD) — Generality, breadth, and the specialist trap Two agents are evaluated on 10 task domains. Agent A scores $(1.0, 0.0, 0.0, \dots, 0.0)$ (perfect on one, zero elsewhere); Agent B scores $0.6$ on all ten. (a) Compare their arithmetic-mean scores and their generality under a breadth-sensitive measure — use the geometric mean as a simple breadth-sensitive aggregate and explain why it penalizes spikiness. (b) The Legg–Hutter measure weights domains by simplicity $2^{-K(\mu)}$. If Agent A's one domain is the simplest (highest weight $0.5$, remaining nine sharing $0.5$ equally), recompute a weighted comparison. (c) What does this reveal about claims of the form "superhuman on benchmark X therefore near-AGI"?
    Solution
    (a) Arithmetic means: A $= 1.0/10 = 0.10$; B $= 0.60$. Geometric means: A $= (1.0 \cdot 0^9)^{1/10} = 0$ (one zero annihilates the product); B $= (0.6^{10})^{1/10} = 0.6$. The geometric mean penalizes spikiness because it's dominated by the weakest dimensions (a single zero → zero); it rewards even, broad competence — the essence of generality (generality-measurement topic: breadth over peak). B is vastly more general. (b) Weighted arithmetic: A $= 0.5 \times 1.0 + \sum_{i=2}^{10}(0.5/9)\times 0 = 0.5$. B $= 0.5\times0.6 + 9\times(0.5/9)\times0.6 = 0.3 + 0.3 = 0.6$. Even giving A's single domain the maximum simplicity weight (0.5), B still wins (0.6 vs 0.5) because B captures the other half of the weighted space that A completely fails. Only if A's domain had weight $> \approx 0.6$ (implausibly dominant) would A win — the simplicity weighting can't rescue a specialist unless its one domain is almost the entire relevant task space. (c) A specialist superhuman on one benchmark contributes only that domain's weighted term to generality; the vast remaining task space it fails dominates any breadth-sensitive or weighted measure. "Superhuman on X → near-AGI" confuses a single high term with the whole sum — the specialist trap (general-purpose-intelligence topic). Generality requires broad, even competence across the distribution; benchmark-topping is one point, and the honest measure (geometric mean, or simplicity-weighted breadth) exposes the difference. This is why AGI evaluation reports profiles and emphasizes novel-task breadth over peak benchmark scores.
    Problem 3 (HARD) — The elicitation gap meets the safety threshold A dangerous-capability eval (Ch 35) must decide whether a model has crossed a threshold requiring stronger safeguards. Under zero-shot prompting the model succeeds on the hazardous-proxy task 8% of the time; under best-effort elicitation (CoT + best-of-32 with a verifier + tools) it succeeds 61%. The threshold is "≥ 40% under realistic misuse conditions." (a) Which number should gate the decision, and why (capability-measurement + Ch 35's elicitation-gap pitfall)? (b) The eval team's best-of-32 uses an imperfect verifier; a fine-tuning-API attacker could plausibly do better. How should this affect the reported number and the safety margin? (c) State the asymmetric-loss argument for how to handle the uncertainty, and connect it to responsible scaling (Ch 35).
    Solution
    (a) The best-effort number (61%), not the zero-shot 8%, must gate the decision. The safety-relevant quantity is what a determined misuser could extract, and misusers will use CoT, sampling, verification, and tools — the polite zero-shot reading (8%) drastically understates deployed capability (the elicitation gap, Ch 35). 61% ≥ 40%, so the threshold is crossed and safeguards trigger. Gating on 8% would be a catastrophic under-elicitation error — declaring safe a model that is not. (b) The 61% is itself likely a lower bound on the true ceiling: the team's verifier is imperfect and fine-tuning access (which removes refusals and specializes the model, Ch 35) can raise capability beyond in-context elicitation. So the reported number should be framed as a floor, and the safety margin should place the decision threshold below the measured value — treat measured 61% as "at least 61%, plausibly higher," and if the threshold were, say, 65%, the honest reading given the elicitation gap would still lean toward "assume crossed" rather than "safely under." Report the capability curve and its trend, not just the point, and include a fine-tuned-variant estimate. (c) Asymmetric loss: the cost of a false "safe" (deploying a dangerous under-safeguarded model) vastly exceeds the cost of a false "unsafe" (applying safeguards unnecessarily). Under asymmetric loss, the optimal decision rule is not to use the point estimate against the threshold but to require confidence that the model is below threshold before declaring safe — i.e., err toward assuming more capability (Bayesian decision theory, Ch 24, with a loss function that heavily penalizes the dangerous error). Connection to responsible scaling (Ch 35): this is exactly why scaling policies (i) elicit at best-effort with margins, (ii) evaluate before thresholds to catch approaching capability early, and (iii) pre-commit to safeguards triggering on the conservative reading — the whole apparatus exists to make the asymmetric-loss-correct decision (assume danger until confidently ruled out) mechanical and immune to in-the-moment pressure to use the flattering 8% number. The measurement feeds a decision whose loss structure demands conservatism, and the governance layer enforces that conservatism. This ties the book's final technical thread — how to measure capability honestly — to its final practical stakes: measurement done wrong, or read optimistically, defeats every safeguard downstream.

    Task 1 — Catastrophic forgetting and EWC. Train a tiny model on two 1-D regression "tasks" sequentially and measure forgetting; then add an Elastic Weight Consolidation penalty using a Fisher-information estimate and show it reduces backward transfer. Reproduces the forgetting explorer's math.

    Reference solution
    import numpy as np

# Two tasks: y = w.x for different target weights; shared params w in R^2.
rng = np.random.default_rng(0)
wA_true, wB_true = np.array([2.0, -1.0]), np.array([-1.0, 2.0])
XA = rng.normal(size=(200, 2)); yA = XA @ wA_true
XB = rng.normal(size=(200, 2)); yB = XB @ wB_true

def fit(X, y, w0, steps=400, lr=0.05, ewc=None):
    w = w0.copy()
    for _ in range(steps):
        g = X.T @ (X @ w - y) / len(y)
        if ewc is not None:
            F, wstar = ewc
            g = g + F * (w - wstar)               # EWC penalty gradient
        w -= lr * g
    return w

def mse(X, y, w): return float(((X @ w - y) ** 2).mean())

w = fit(XA, yA, np.zeros(2))                        # learn A
print("after A:  MSE_A=%.3f MSE_B=%.3f" % (mse(XA, yA, w), mse(XB, yB, w)))
w_noEWC = fit(XB, yB, w)                            # learn B, no protection
print("after B (no EWC):  MSE_A=%.3f MSE_B=%.3f" % (mse(XA, yA, w_noEWC), mse(XB, yB, w_noEWC)))

# Fisher diag for task A at w (Fisher = E[grad_loglik^2]; here ~ diag(X_A^T X_A)/n)
F = np.diag(XA.T @ XA) / len(yA) * 20.0            # scaled importance (lambda folded in)
w_EWC = fit(XB, yB, w, ewc=(F, w.copy()))
print("after B (EWC):     MSE_A=%.3f MSE_B=%.3f" % (mse(XA, yA, w_EWC), mse(XB, yB, w_EWC)))
# No-EWC forgets A (MSE_A explodes); EWC keeps A low at a small cost to B.

    Task 2 — Capability-vs-compute curve (best-of-n with a verifier). Simulate a generator with per-attempt success probability $p$ and a verifier with false-accept/false-reject rates; compute delivered success under best-of-$n$ and plot the capability curve, showing how a single-attempt measurement understates the ceiling.

    Reference solution
    import numpy as np

def delivered_success(p, n, fa=0.05, fr=0.05, trials=20000, seed=0):
    rng = np.random.default_rng(seed)
    wins = 0
    for _ in range(trials):
        accepted_good = False
        for _ in range(n):
            good = rng.random() < p
            accept = (rng.random() < (1 - fr)) if good else (rng.random() < fa)
            if accept:
                accepted_good = good      # return first accepted; success if it's good
                break
        wins += accepted_good
    return wins / trials

p = 0.2
print("per-attempt (n=1, no verifier proxy): %.3f" % p)
for n in (1, 2, 4, 8, 16, 32):
    print(f"best-of-{n:2d}: delivered success = {delivered_success(p, n):.3f}")
# Rises steeply from ~0.2 toward a ceiling set by verifier false-accepts:

    Task 3 — Generality profile and breadth-sensitive scoring. Given per-domain scores, compute arithmetic mean, geometric mean, and a simplicity-weighted score, and demonstrate that a spiky specialist and an even generalist with equal arithmetic mean differ sharply under breadth-sensitive aggregation (Capstone Problem 2).

    Reference solution
    import numpy as np

def scores_report(scores, weights=None):
    s = np.asarray(scores, float)
    arith = s.mean()
    geo = np.exp(np.mean(np.log(np.clip(s, 1e-9, 1))))     # geometric mean
    if weights is None: weights = np.ones_like(s) / len(s)
    weights = np.asarray(weights, float); weights /= weights.sum()
    wmean = float(weights @ s)
    return dict(arithmetic=arith, geometric=geo, weighted=wmean, min=float(s.min()))

specialist = [1.0] + [0.0] * 9          # perfect on one domain
generalist = [0.6] * 10                 # even competence
print("specialist:", {k: round(v, 3) for k, v in scores_report(specialist).items()})
print("generalist:", {k: round(v, 3) for k, v in scores_report(generalist).items()})
# Simplicity weights: domain 0 simplest (0.5), rest share 0.5
w = [0.5] + [0.5 / 9] * 9
print("specialist (simplicity-weighted):", round(scores_report(specialist, w)['weighted'], 3))
print("generalist (simplicity-weighted):", round(scores_report(generalist, w)['weighted'], 3))
# geometric mean: specialist -> 0 (a single zero annihilates), generalist -> 0.6:
# breadth-sensitive measures expose the specialist trap even at equal-ish means.
